# 需求与范围

## 为谁做

为单个用户自己使用。系统只看这个用户自己的记录，不做跨用户比较，也不训练面向所有人的模型。

## 要解决的问题

1. 目标太大、太模糊，不知道今天先做什么。
2. 每天任务量忽高忽低，有时排太多做不完，有时排太少。
3. 临时出现的事情会打乱计划，长期任务容易被一直往后推。
4. 学习型任务需要隔一段时间再练，但容易忘。
5. 做完一天的事之后，系统不能继续打扰，用户要能安心停下来。

## 三个核心结果

1. **目标能拆成今天能动手的任务**：每条任务有完成标准、估计用时、类型和前置关系。
2. **每天的任务量合适**：不超过当天可用时间；长期任务有等待上限；临时任务有地方接。
3. **系统会根据自己的记录修正**：用时估计、完成情况、状态变化能进入后面的安排；用户可以看到依据并手动纠正。

## 范围

做：

- 目标管理、任务拆解、任务确认。
- 稳定特质、每日状态、单任务预测。
- 每天可用时间、任务分配、截止任务、长期任务、当天杂事。
- 执行记录、每日反馈、原因判断、顺延/小修/大改。
- 研究证据与验证。

不做：

- 跨用户模型、群体比较。
- 完整复习系统（记忆曲线、错题本、复习队列）。
- 压力趋势预测；只做状态估计和阈值处理。
- 多人协作、团队排期。
- 复杂账号体系。
- 用大模型直接排任务。

## 约束

- 单用户，数据来自用户自己的记录。
- 用户不一定每天记录执行细节；缺失数据要能处理。
- 排任务必须是确定性规则，不能依赖大模型。
- 预测只是输入，不能直接改硬约束。
- 反思文本可能包含隐私；需要脱敏、保留期和删除/导出。

## 怎样算有用

- 每天的计划不超出用户设定的可用时间。
- 长期任务不会无限期排不上。
- 临时任务出现时，系统能给出可执行的取舍，而不是硬塞。
- 用户完成当天任务后，系统明确结束，不再打扰。
- 用了一段时间后，用时估计比一开始更接近实际；如果做不到，系统不假装“已经懂你”。
