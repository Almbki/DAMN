# 实施指导

> 当前代码是远端 `V1.1-test`，不是一张白纸。这页是“从当前代码到目标设计”的差距计划；先读 [当前实现.md](当前实现.md) 知道现状，再按阶段改。具体怎么改要拉仓库看代码、跑测试、读 `AGENTS.md`，不要只按文档写代码。

## 开始之前

- 先读根目录 `AGENTS.md`：命令、目录规则、测试方式、前端约束。
- 先跑现有测试，确认基线；再决定保留哪些、重写哪些。
- `models_test/` 是参考和测试，不是运行时依赖；不要 import 它，按它的字段在自己的代码里实现。
- 不要先搭展示层；文档只用 Markdown。

## 保留与重写

**保留**：

- 配置、密码哈希、登录、数据库会话、迁移基线。
- 测试脚手架和环境变量纪律。
- 大模型客户端的接口抽象。
- 预测器的接口契约。

**重写**：

- 旧的拆解节点、旧的预测器实现、旧的排程逻辑。
- 旧的反馈/重排逻辑。
- 旧的数据表：按新的任务、执行、反思、证据、状态、预测、结果重新设计。

## 阶段

### 阶段 0：读代码与对齐 schema

**做什么**：

- 读当前 `app/` 的分层、模型、服务、接口。
- 把 `models_test/` 的字段作为 schema 基线：任务计划、任务执行、反思、证据、每日状态、第三层输入输出、结果记录。
- 列出我们额外需要的字段：完成标准、前置任务、价值、任务类型、拆分单位、锁定、可排日期。

**产出**：一份字段清单和迁移计划。

**验收**：字段没有两套叫法；拆解、排程、预测三层都能在同一套任务/执行记录上工作。

### 阶段 1：数据与记录

**做什么**：

- 建任务、执行、反思、证据、状态、预测、结果的数据表和迁移。
- 记录完成、部分完成、没做、没做原因、每日反馈、用户修正。
- 执行细节可选：实际开始、实际时长、打断次数可以为空；不要强制计时。

**产出**：可写入、可查询的记录层。

**验收**：完成/部分/没做都能落库；缺失执行细节不会报错；历史可以回放。

### 阶段 2：三层用户模型

**做什么**：

- 第一层：接入人格题自适应测试，输出五个维度的分数和不确定度；允许跳过。
- 第二层：接入每日状态更新；四段反思可选；大模型抽证据，规则兜底。
- 第三层：接入冷启动和历史基线；学习模型保持关闭。
- 预测结果写入快照；不要用任务后信息回填。

**产出**：稳定特质、每日状态、单任务预测三个服务。

**验收**：

- 第一层：题目能走完，输出分数和不确定度。
- 第二层：有反思/任务记录时能更新状态；没有数据时标记证据不足，不编状态。
- 第三层：冷启动用时等于估计、完成概率为空；有历史后能用历史基线。
- 不声称预测准确。

### 阶段 3：拆任务

**做什么**：

- 目标输入 → 直接生成任务草案；不追问。
- 每条任务可以有描述；没有描述时用默认完成标记。
- 只做基础格式检查：格式、必填、类型、编号唯一、时长为正、前置成环、类型/单位一致。
- 用户手改或改提示重试，最多两次；失败交回用户。

**产出**：可确认的任务草案。

**验收**：草案能落库；格式错误能被拦住；任务过大/覆盖不足只提示，不硬拒；用户确认是唯一生效入口。

### 阶段 4：每天安排

**做什么**：

- 每天可用时间 = 每日可用工作时间 − 固定负载；固定负载可选。
- 按顺序使用时间：钉死任务、突发空位、长期任务最低额度、截止任务、当天杂事。
- 截止任务装不下时走三选一；长期任务有最长等待；当天杂事每天重排。
- 第二档偏离只重排未来三天，不改任务内容；超过每天可用时间就进第三档。
- 排任务不调用大模型。

**产出**：每日计划、装不下清单、理由记录。

**验收**：计划不超过可用时间；长期任务有等待上限；装不下有可见处理；计划版本可回放。

### 阶段 5：反馈与结束

**做什么**：

- 每日反馈和任务后反馈；四段反思可选。
- 判断状态差、安排不合适、不知道原因。
- 顺延、小修、大改三档；大改有冷却。
- 当天完成或明确跳过后提示结束，当天不再打扰。

**产出**：反馈记录、原因判断、重排/重拆记录。

**验收**：状态差不污染长期估计；顺延挤爆明天仍能处理；结束提示后不再打扰。

### 阶段 6：检验与试点

**做什么**：

- 在电脑里模拟不同情况的使用者，观察完成率、最长等待、稳定性、按时率、长期推进、打扰、利用率。
- 用真实记录做前后比较；不要求数学检验，只看变化是否大于日常波动。

**产出**：验证记录和结论。

**验收**：机制按设计工作；没有真实数据就不声称预测准确；不达标就回退，不继续加复杂度。

## 开始写代码前还要定的

- 第二层四段反思：每天提示还是只在用户主动打开时出现。
- `TaskPlan.planned_start` 的默认值：只给日期时怎么设开始时间。
- 隐私与安全的最小落地顺序：脱敏、保留期、删除/导出、危机提示。
- 长期任务最长等待、突发预留、截止任务加速阈值等具体数值。
