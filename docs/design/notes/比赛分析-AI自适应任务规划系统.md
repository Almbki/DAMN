## 一、系统概述与产品定位

### 1.1 系统是什么

本系统是一个 **AI 驱动的自适应任务规划助手**。用户输入一份目标清单（如暑假计划），系统将其智能拆解为 **每日任务计划 + 每周任务拆分 + 每日/每周反馈复盘**，并通过反馈驱动持续迭代计划，最终帮助用户在时间截止前完成目标，同时避免焦虑与拖延。

### 1.2 目标用户

| 用户群体 | 痛点 |
|---------|------|
| **完美主义 / 焦虑者** | 总觉得"学得不够"，无法安心休息 |
| **拖延症人群** | 计划永远赶不上变化，越拖越焦虑 |
| **考研 / 考公 / 考证人群** | 多科目并行，时间管理复杂度高 |
| **学生群体（中学生/大学生）** | 假期或学期目标管理 |
| **自律困难者 / 兴趣广泛者** | 学习、健身、爱好多条线并行难以平衡 |

### 1.3 核心定位

> **"完成即安心"的反焦虑自适应规划引擎**
> 不是让你学得更久，而是让你在有限时间内完成该做的事，然后**放心地玩**。

## 二、创新点总结（对照"创新性"评分维度）

### 创新点 1：反馈驱动的动态迭代规划（核心创新）

传统任务计划是**静态的**——做完就扔；本系统是**活的**——每天根据执行反馈自动重排。

```
初始计划 → 执行(每日勾选/日志) → 反馈(完成率/压力/原因) → 计划重排 → 下一版
```

| 迭代 | 触发信号 | 调整动作 |
|------|---------|---------|
| v1→v2 | 用户反馈"数学时间不够、午休躺床睡不着" | 增加缓冲时间、调整午休、拆分完成标准 |
| v2→v3 | 周记反馈"数学+算法同天太累、C++优先级应更高" | 上午只排1个核心任务、数学/算法不同天、权重调整 |
| v3→v4 | 执行率下降（7/24起未执行）、8/31硬性截止目标 | 数学冲刺模式、恢复每日/每周总结、重排全部任务 |

**本质是"RLHF 思想"在任务规划领域的应用**：用人类执行反馈（而非模型打分）持续校正输出计划，形成**规划→执行→反馈→再规划**的闭环。

### 创新点 2：认知负荷调度模型

系统将任务按认知消耗分级，并进行智能调度：

| 等级 | 标签 | 示例 | 调度规则 |
|------|------|------|---------|
| 🔴 高认知 | 数学、算法、408 | 需最高专注 | 排在最清醒时段（早晨），1天不超过1个连续 |
| 🟡 中认知 | 线代、编程、六级 | 中等消耗 | 排次优时段 |
| 🟢 项目 | 智能体开发、硬件 | 创造性 | 下午时段 |
| 🎸/🏋️/📖 | 练琴、锻炼、英语 | 轻量恢复 | 穿插在高认知任务之间，作为"认知休息" |

**关键规则（来自迭代沉淀）：**
- 高认知任务之间间隔 ≥ 30min，中间插入锻炼/练琴
- **数学与算法不同天**（同类重认知任务扎堆导致效率下降）
- 下午犯困时段（约15:30）安排高强度锻炼对抗

这是**认知科学 × 任务调度的创新融合**。

### 创新点 3：反焦虑设计哲学

系统的第一目标不是"提高学习时长"，而是"让用户安心"：

- **完成即休息**：每天核心任务勾完后，剩余时间自由支配，明确"不玩也没事"
- **自由活动选项清单**：解决"不知道干什么→没事干→焦虑→无法进入休息状态"的恶性循环
- **限时原则**：任务标注净时+缓冲，超时即停，杜绝"永远学不完"的失控感
- **缓冲机制**：任务间预留15-20min，吸收收尾溢出，避免"上一个任务没做完就赶下一个"的挫败感

**切中完美主义/焦虑/拖延人群的核心心理诉求**，是产品差异化的重要来源。

### 创新点 4：完成标准的可量化拆解

将模糊的"完成"（如"复习数学第1章"）拆解为可勾选的子标准：

```
□ 📺 看网课视频
□ ✏️ 做网课例题（标记不会的）
□ 📝 吉米多维奇对应习题3-5道
□ 📋 总结知识点
```

- 消除了"什么叫学完了"的歧义
- 每完成一个子项都有即时正反馈（进度感）
- 未完成的子项精确暴露"卡在哪一步"（如只看完视频没做题）

### 创新点 5：人类生物钟与生活现实的适配

系统不是冷冰冰的时间表，而是**尊重真实生活的计划**：

- 特殊日管理：朋友聚会、电影日、旅行日自动降载为"轻量日"
- 生物钟适配：根据"午休躺床睡不着"反馈，迭代为"午餐+站立休息"，再迭代为"允许45min午睡"
- 弹性日制度：每周日自动降载，安排采购备餐、攀岩等生活事务
- 洗澡时间、犯困时段等真实生活细节被纳入调度

## 三、系统优势分析

### 3.1 相比同类产品的优势

| 对比项 | 传统待办清单（Todo App） | 传统日程表 | 本系统 |
|--------|------------------------|-----------|--------|
| 任务拆解 | 用户手动 | 用户手动 | **AI 自动拆解到每日/每周** |
| 计划调整 | 不调整 | 手动调 | **自动按反馈迭代** |
| 完成标准 | 无 | 无 | **可量化子标准** |
| 认知调度 | 无 | 无 | **高/中认知分级调度** |
| 心理关怀 | 无 | 无 | **反焦虑设计哲学** |
| 反馈闭环 | 仅勾选 | 无 | **日志+周记→计划重排** |
| 多目标并行 | 差 | 差 | **多科目/多兴趣自动平衡** |

### 3.2 数据与模式优势

- **迭代痕迹即数据资产**：v1→v4 的每次调整，本质是"人类偏好数据集"，可用于微调模型或构建规则引擎
- **低门槛高价值**：输入一份目标清单即可获得完整可执行的动态计划，对用户零学习成本
- **通用可复制**：暑假计划只是第一个应用场景，可复制到学期计划、备考计划、项目排期、人生目标管理

### 3.3 与比赛主题的契合度

- 深度融合 AI：LLM 负责拆解、调度、复盘、重排
- 是**已完成开发**的原型（本套 md 计划体系即为可运行的初版）
- 有明确应用价值和真实用户（用户本人已连续使用4周并反馈迭代）
- 有真实使用数据（4个版本的执行率、完成情况、压力反馈）

## 五、核心内容提炼（产品化后是什么）

### 5.1 一句话定位

> **「认知负载引擎」**——一款 AI 驱动的、基于人类执行反馈持续自适应重排计划的智能任务规划软件，专为焦虑、拖延与多目标并行人群设计。

### 5.2 核心功能模块

```
┌─────────────────────────────────────────────────┐
│               AI 自适应任务规划系统               │
├─────────────────────────────────────────────────┤
│  ① 目标拆解引擎    │  输入目标 → AI拆解为周/日计划   │
│  ② 认知负荷调度器  │  高/中认知分级 + 调度规则引擎    │
│  ③ 反馈采集模块    │  每日日志 + 每周周记（结构化）    │
│  ④ 自适应重排引擎  │  基于反馈 → 调整排期/权重/节奏   │
│  ⑤ 数据洞察面板    │  完成率/压力指数/耗时预测可视化   │
│  ⑥ 提醒与集成      │  日历同步/定时提醒/多端同步      │
└─────────────────────────────────────────────────┘
```

### 5.3 技术核心点

1. **规划状态机**：`初始规划 → 执行 → 反馈采集 → 状态评估 → 重规划`，形成闭环
2. **结构化反馈协议**：将自由文本日志转化为结构化数据（完成率/压力指数/未完成原因分类/耗时），供重排引擎消费
3. **多 Agent 协作**：规划 Agent（拆解）、调度 Agent（认知编排）、复盘 Agent（分析反馈）、洞察 Agent（数据统计）
4. **规则 + LLM 混合**：硬规则（数学算法不同天、高认知不连续、缓冲机制）用规则引擎保证，软性拆解/总结用 LLM

### 5.4 差异化卖点（对外宣传）

- **不是又一个待办清单，而是会"反省"自己的计划**
- **唯一把认知科学（认知负荷、生物节律）工程化到任务调度的产品**
- **专为"学不下去又放不下"的人群设计**

## 八、总结

本套体系的核心竞争力在于 **"反馈驱动的动态规划闭环"**——这不是一个静态工具，而是一个会随着使用者执行情况不断自我修正的智能系统。它在创新性（反馈迭代+认知调度+反焦虑设计）和应用价值（焦虑/拖延/备考人群痛点明确）上有天然优势，当前最大的短板是**尚未工程化为完整软件产品**。

**建议路径**：以 v1→v4 的迭代成果作为"已验证的原型"，将其工程化为 Web 应用（前端交互 + 后端持久化 + LLM 规划引擎 + 数据看板），补齐功能完整性与方案文档，即可形成竞争力较强的参赛作品。
