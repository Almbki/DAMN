# 系统架构

> 这页是**目标设计**，不是当前代码。当前代码 `V1.1-test` 的实际行为见 [当前实现.md](当前实现.md)；从现状到目标的差距见 [实施指导.md](实施指导.md)。读代码前先分清这两层。

## 一句话

系统先把目标拆成任务，再估计人和任务的情况，然后安排每天做哪些任务；做完后记录实际发生的事，判断没做好的原因，再调整后面的估计和安排。

整个循环是：

```
目标 → 拆任务 → 估计 → 每天安排 → 执行 → 记录 → 判断原因 → 调整
```

## 六个部分

### 1. 记录

记录任务实际发生了什么：完成、做了一部分、没做；没做的原因；每天的状态反馈；用户对估计的修正。

记录不是为了好看，是为了让后面的估计有依据。没有记录，系统只能按规则排任务，不会变准。

记录的原则：

- 只追加，不修改历史；修正用新记录表达。
- 完成、部分完成、没做都是一等记录，不能只记完成。
- 没做要区分“当天状态不行”和“安排不合适”，否则完成率会被状态问题污染。
- 不要求用户记录每次专注的起止时间；执行细节可以留空，模型会标记证据不足。

### 2. 拆任务

把一个目标拆成可以执行的任务。每条任务至少要有：做什么、做到什么程度算完成、大概要多久、什么类型、有没有前置任务。

拆解的原则：

- 先确定完成标准，再拆任务。没有完成标准，拆出来的任务可能全做完，目标还没达成。
- 由大模型生成草案，但草案必须经过基础格式检查，并由用户确认后才生效。
- 不做复杂的质量硬门。只保留会导致程序出错或数据损坏的检查；任务是否过大、目标是否覆盖，交给大模型和用户判断。
- 用户不满意可以手改，或者改提示后重试，最多两次；修不好就交回用户手工处理。
- 拆解不排日期；任务能不能装进某一天，由每天安排那一层判断。

### 3. 估计人与任务

这一层分三层：

- **稳定特质**：用一套人格题估计用户长期稳定的倾向，只作背景，不当作每天的状态。
- **每日状态**：用当天的任务记录和可选反思，估计疲劳、压力、自我效能。
- **单任务预测**：结合稳定特质、任务前状态、任务本身和历史，预测这个任务能不能完成、实际要多久。

边界：

- 稳定特质不能冒充每日状态。
- 单任务预测只用任务前的状态，不用任务后的信息，不回填。
- 预测只是排任务的输入，不直接决定排程。
- 学习模型在数据不够时保持关闭；先用冷启动和历史基线。

### 4. 每天安排

每天安排要解决两个问题：今天能用多少时间，以及这些时间先给谁、任务放在哪一天。

每天可用时间：

```
每天可用时间 = max(0, 每日可用工作时间 − 固定负载)
```

- 每日可用工作时间由用户设定，可以只是一个固定的数。
- 固定负载是课表、上班或其它已经占用的时间；用户可以不填，默认按零处理。
- 当天可以覆盖默认值。
- 固定负载超过每日可用工作时间时，当天可用时间算零，任务顺延。

每天的时间按顺序使用：

1. 先扣掉用户钉死、不能移动的任务。
2. 留出一部分不安排，用于接收临时出现、必须当天处理的任务。
3. 给需要长期反复做的任务留一个最低额度。
4. 剩下的时间先满足有截止日的任务。
5. 最后剩下的时间给当天杂事。

任务放在哪一天：只放在最早可开始日期和截止日期之间；选择放入后每天工作量最平均的那一天；一样平均时选更早的一天；放不下就换一天；仍然放不下就告诉用户，不硬塞。

跑偏后的处理：

- 只是今天没做完：顺延到明天，不改估计。
- 顺延把明天挤爆，或者连续几天完成率低且原因是安排问题：只对未来三天重新排序，不改任务内容，不涉及大模型。
- 第二档连续无效、截止不可能、目标变化：重排或重拆，大改有冷却。
- 状态差跳过：不改长期估计；如果顺延挤爆明天，仍然处理，但只允许延期或换时段。

### 5. 判断原因

任务没完成时，先判断原因：

- **状态差**：疲劳、压力、临时事务。不改长期估计，顺延。
- **安排不合适**：任务太大、太难、时间估错。小范围调整，长期估计按周慢慢修正。
- **不知道原因**：不改、不升级；连续多天不知道，做一次只减量、不改估计的体检。

当天所有任务完成或明确跳过之后，系统提示“今天干完了”，当天不再打扰。

### 6. 检验

先在电脑里模拟不同情况的使用者，观察完成率、最长等待、计划稳定性、截止任务按时率、长期任务推进、打扰次数、时间利用率。

再用用户自己的真实记录做前后比较。个人记录每周只有七天，波动大，不要求数学检验，只看变化是否明显大于日常波动。

检验只能证明机制是否按设计工作，不能证明真实使用者会怎样；真实效果要持续使用一段时间才能判断。

## 三条不变规则

1. **硬约束由规则决定**：可用时间、截止日期、前置关系这些硬约束，不能由大模型或预测模型直接改。
2. **排任务不调用大模型**：拆任务和重拆可以调用；每天安排、排序、装不下处理都是确定性规则。
3. **记录只追加**：历史不修改；修正用新记录表达，所有结论可以回溯。

## 现在没做的

- 学习模型没有训练，保持关闭。
- 不把状态和预测存成 JSON 文件；用数据库。
- 不接 `models_test` 的排程代码；排程仍由我们的规则做。
- 不做跨用户模型；只看单个用户自己的记录。
- 不做完整复习系统；学习型任务只做安排规则。
