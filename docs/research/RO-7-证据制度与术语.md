## 4. 方案设计

### 4.1 三类标记（怎么分辨"文献结论"还是"编的"）

| 标记 | 含义 | 可信度 | 工程处置 |
|---|---|---|---|
| **【文献】** | 文献直接结论，附 `方向N [n]` | 最高，可回查原文条目 | 可作为规则/默认行为依据 |
| **【外推】** | 文献结论方向正确，但具体数值/机制是推导的 | 中，需实验校准 | 可做默认，但要留开关与监控 |
| **【工程】** | 文献没有，纯工程经验设定 | 低，必须实验校准 | 写成可调参数，不可当科学结论 |
| `文献库无直接证据` | 检索过但没有对应卡片 | 无 | 不得用"通常认为/业界普遍"填充 |

**规则**（`AGENTS.md` R1/R2）：只能基于提供的文献卡片/笔记回答；每个技术判断后必须加 `[卡片ID]`；非文献内容标 `【推断】/【未调研】`；没有任何卡片支撑时必须写「文献库无直接证据」。

### 4.2 五档证据强度

| 档位 | 含义 | 工程动作 |
|---|---|---|
| `强` | 元分析 / 大样本 RCT / 权威系统综述 | 可直接固化为规则或默认行为 |
| `中强` | 高质量单研究或多个一致研究 / 权威综述 | 可做默认，但要留开关与监控 |
| `中` | 单研究 / 概念综述 / 小样本 | 先"影子运行"（只记录不拦截），条件满足再固化 |
| `理论` | 框架 / 建模 / 权威意见 | 作为设计说明与假设来源，不作为硬规则依据 |
| `⚠` | 预印本 / 撤稿 / 仅据题录且摘要不可得 | 只能作方向参考，**不得单独作为设计依据** |

**必须降级使用的条目**：
- **已撤稿（仅作争议背景，不得作设计依据）**：方向2 [13]（Ariely & Wertenbroch 2002，2012 年撤回）。
- **预印本/工作论文**：方向4 [7]（SSRN）、方向4 [33]（medRxiv）、方向4 [39]（PsyArXiv）。
- **摘要不可得、仅据题录**：方向3 [7][19][22][29][30][34]；方向4 [1][2][6][10][12][15][17][19][27][28][29][30][31][34][37]；方向5 [4][14]；方向2/6/9/11 见各自 `papers.md`。
- **设备依赖（行为层结论可用，不采同类生理信号）**：fMRI 方向1 [18]、方向3 [32][33]、方向8 [18]、方向11 [8]；HRV/皮质醇/冷压 方向1 [19]、方向6 [9][10][21]；TMS/EEG 方向7 [9]；VR/动作捕捉 方向9 [31]。

### 4.3 卡片制度（13 字段）

**卡片** = 对应 `papers.md` 中一个编号条目，含 13 字段：

| # | 字段 | 用途 |
|---|---|---|
| 1 | 研究问题 | 该文回答什么 |
| 2 | 核心理论 | 机制/框架 |
| 3 | IV 自变量 | 被改变/被比较的因素 |
| 4 | DV 因变量 | 被测量的结果 |
| 5 | 主要结论 | 可落地的结论 |
| 6 | 证据强度 | 元分析/综述/单研究/框架等 |
| 7 | 研究局限 | 外推边界 |
| 8 | 与本项目的关系 | 对系统的意义 |
| 9 | 支持的系统设计 | 具体设计动作 |
| 10 | 可采集数据 | 日志/自评/行为信号 |
| 11 | 可形成的 User State | 候选状态字段 |
| 12 | 可成为哪一部分 | Rule / Model / Harness / Scheduler 等 |
| 13 | 推荐优先级 | ★ 等级 |

**ID 规则**：`方向N [n]`，N=01–11，n 为该文件内编号；**编号永不复用**。
**新增卡片**：只能在对应 `papers.md` 末尾追加编号，且必须：① 实际检索获得（记录检索式/日期/来源库）；② 完整填写 13 字段；③ 记录 DOI/链接并核验可访问；④ 同步更新文件头"检索 N 篇，采纳 M 篇"统计；⑤ 同步更新 `研究状态.md`（RO-1 计数 + 全局变更日志）。
**禁止**：凭记忆补条目；删除或重排既有编号（如需更正，保留原条目并追加更正说明）。

1. **`术语表.md`** —— 先建立术语口径，避免各说各话；

**回答之后必须更新 `研究状态.md`**（AGENTS.md 强制）：把结果写入**对应 RO 节**——新结论→该 RO 的"已确认结论"；新决策→该 RO 的"决策记录"（用全局唯一 `D-x` 编号）；新问题→该 RO 的"未决问题"；若内容跨越现有 RO，则**新建 RO**（索引 + 节，模板见文件末尾）；最后在"变更日志"追加一行。

### 1. 硬性规则（违反即为不合格输出）

**R1｜只能基于提供的文献卡片/笔记回答。**
没有任何卡片支撑的内容，必须写 **「文献库无直接证据」**，不得用"通常认为""业界普遍"等模糊说法填充。

**R2｜每个技术判断后必须加 `[卡片ID]`；非文献内容标 `[推断]` / `[未调研]`。**
卡片ID格式：`方向N [n]`（例：`方向4 [39]`）。三类标记的定义与判定标准见 `RO-7-证据制度与术语.md` §4.7（溯源审计）：

| 标记 | 含义 |
|---|---|
| `[方向N [n]]` | 文献直接结论，可回查该卡片 |
| `[推断]` | 从文献外推：方向有依据，但具体数值/机制是推导 |
| `[工程]` | 文献无支撑的工程设定，必须实验校准 |
| `[未调研]` | 文献库无证据，属待验证假设 |
| `文献库无直接证据` | 检索过但没有对应卡片，直接写这七个字 |

**R3｜每个缩写/专业名称首次出现，必须写入 `术语表.md`。**
若 `术语表.md` 中查不到 → 立即按"新增协议"追加条目（通俗解释 + 例子 + 证据ID），再继续回答。

**R4｜不要直接给单一方案，优先给多方案对比。**
对比维度至少包含：

| 方案 | 定义 | 适用场景 | 证据ID | 效果 | 局限 |
|---|---|---|---|---|---|

### 2. 方案生成任务的补充约束（防止忽略调研、防止目标不透明）

> 适用于任何"根据调研出方案/设计/选型"的请求。以下为用户规则的补充，可按需扩展。

**C1｜先声明目标，再给方案（透明化）**
开篇必须显式列出：

```text
【问题陈述】要解决什么（一句话）
【成功判据】怎样算解决（可观测指标）
【约束条件】技术/成本/合规/已有架构约束
【本次不做什么】范围外事项
【所用证据清单】本次引用的全部卡片ID（先列清单，再引用）
```

**C2｜证据门槛**
- 每个方案至少锚定 1 张卡片；**核心结论必须 ≥1 张强度为"强/中强"的卡片**，否则标注 `[推断]`；
- 引用前必须回查该卡片「主要结论 / 研究局限」两栏，确认支撑关系（不得只凭编号）；
- 明确区分"规则方向来自文献"与"分界线数值是工程默认"。

**C3｜禁止清单**
- ❌ 编造文献、编号、DOI、作者年份；
- ❌ 把各 RO 文档 §8「溯源审计」中标【工程】的数字当文献结论引用；
- ❌ 用撤稿/预印本卡片支撑设计决策（例：`方向2 [13]` 已撤稿，仅供争议背景）；
- ❌ 未经检索就补文献（此前发生过，见方向 10 检索记录中"凭记忆 ID 被 API 纠正"）；
- ❌ 只给方案不给触发条件、降级路径与验证方式。

**C4｜方案必须自带"可失败性"**
每个方案给出：适用边界、失效条件、降级方案、最小验证实验（MVE）与判据。只给"推荐做法"而不给"什么情况下不适用"的方案视为不合格。

**C5｜冲突要暴露，不要私自调和**
- 卡片之间冲突 → 并列呈现 + 标注证据强度差异 + 说明为何选其一（或给出两方案）；
- 文献与项目现状（AGENTS.md 根目录架构约定）冲突 → 明确说明冲突点，交用户决策；
- 无法判断 → 写"文献库无直接证据"，并写入 `研究状态.md` 中**相关 RO 的「未决问题」**。

**C6｜输出长度与结构**
- 先结论、后依据；表格优先；
- 关键判断逐条带卡片ID；
- 末尾附：`所用卡片清单` + `本文新增的【推断】/【工程】项` + `建议写入研究状态.md 的条目（指明 RO）`。

### 3. 卡片制度

- **卡片** = 对应 `papers.md` 中一个编号条目，含 13 字段：研究问题 / 核心理论 / IV / DV / 主要结论 / 证据强度 / 研究局限 / 与本项目关系 / 可支持的系统设计 / 可采集数据 / 可形成 User State / 可落点（Rule/统计/ML/LLM Harness）/ 推荐优先级。
- **ID**：`方向N [n]`，N=01–11，n=该文件内编号；**编号永不复用**。
- **新增卡片**：只能在对应 `papers.md` 末尾追加编号，且必须：
  1. 实际检索获得（记录检索式、日期、来源库）；
  2. 完整填写 13 字段；
  3. 记录 DOI/链接并核验可访问；
  4. 同步更新该文件头部的"检索 N 篇，采纳 M 篇"统计；
  5. 同步更新 `研究状态.md`：RO-1「参考资料」计数 + 全局「变更日志」。
- **禁止**：凭记忆补条目；删除或重排既有编号（如需更正，保留原条目并追加更正说明）。

### 4. 复核方法（任何人可做）

1. 正文看到 `方向N [n]` → 打开 `docs/research/<N>-*/papers.md`；
2. 在 GB/T 7714 清单与逐篇分析中找到 `[n]`；
3. 读其「主要结论 / 研究局限」，判断是否支撑该论断；
4. 原始检索数据在 `<N>-*/api/`（方向 10 除外）；
5. DOI 可访问性记录见 `DOI链接验证记录.txt`。

### 4.6 复核方法

**目标**：任何一条结论，都能沿"引用编号 → DOI → api/ 留档 → 原始检索"逆向验证。

1. **核对检索式与命中规模**：打开 `api/f1_search_provenance.txt`（01/07）或 `f7_search_provenance.txt`，确认文件头声明的检索式组数与命中数一致；其余方向查看 `api/candidates_0X.txt`、`ranked_0X.txt`、`raw_*.json` 的 `meta.count`。
2. **核对采纳文献 DOI 可解析性**：
   - 方式 A（全局速查）：`DOI链接验证记录.txt`，按方向 ID 找目标 DOI；`200/302` 视为可解析，`403` 为反爬拦截（DOI 服务可解析，不代表文献不存在）。
   - 方式 B（单篇权威元数据）：`NN-方向名/api/verify/<safe_doi>.json`；`verify/DIGEST.txt` 是批量可读汇总。
   - 方式 C（重跑）：`python check_links.py` 或 `python verify_dois.py <outdir> <doi...>`；重跑前先备份 `api/verify/`。
3. **核对降级声明**：`papers.md` 文件头会声明哪些条目"摘要不可得/仅据题录"；对应查看 `api/selected_abstracts_0X.txt`、`_accepted_abstracts.txt`、`fX_adopted_N_readable.txt`；`DIGEST.txt` 中的 `FAIL ... HTTP 429` 行即当时未取到的如实记录。
4. **交叉核对汇总映射**：任取 `方向N [编号]`，回到对应 `papers.md` 第 `[n]` 段，确认与字段 5/6/8/12 一致；汇总文档头部已列降级清单，优先核对这几类。
5. **适用本 7 份 RO 文档**：本系列文档每条设计判断都带证据ID或标记；复核时按上述 1–4 步即可。

**已知留档缺口（必须知道）**：
- **方向 10（LLM 规划与 Harness）没有 `api/` 目录**，仅凭 `papers.md` 文件头声明"arXiv API + Semantic Scholar 批量核实"；严格复核需按文件头检索式重新抓取留档。
- `fetch_*.ps1` / `*.py` 是当时的执行留痕，依赖外部 API 与网络环境，**不保证当前可直接重跑**；重跑命中会与当时不同，属正常现象。
- 中文库（CNKI/万方）未检索；`scr/` 为脚本副本，非资料；部分卡片标注"摘要不可得"。

**F1. 我只有不到 100 个用户，能上 ML 吗？**
不建议。文献路线是"冷启动用简单可解释模型，数据足够再升级"（方向4 [29][30]；方向11 [9][11]）。100 个用户时优先把"理论时间 × 用户倍率"和 BKT/规则做扎实，并用主动学习挑选信息量最大的任务来加速个性化（方向4 [30]）。

**F2. 没有 KLM 理论时间数据怎么办？**
理论时间不是必须由 KLM 计算；可以先用"任务模板的历史中位数"作为 `theoretical_duration` 代理，再乘用户倍率。KLM/GOMS 只是让理论时间更有依据（方向4 [10][11]）。对纯认知任务（如"理解极限定义"），重点放在历史耗时与用户倍率上。

**F3. 用户不填自评怎么办？**
优先用行为代理。疲劳可用反应时个体内变异性（方向1 [6]）与输入动力学（方向1 [9]）；精力/情绪只在关键节点用单题（方向1 [21]；方向4 [39]）。自评是"补充"，不是"必需"（方向11 [14][15]）。

**F4. LLM 预算有限，先砍哪里？**
先砍"可形式化/规则可覆盖"的调用（方向10 [1][2][3][12]），再砍"有相似历史成功计划可复用"的调用（方向10 [13][14]），最后才对语义任务做任务级路由与级联（方向10 [1][2][5]）。上线前用离线基准验证"路由是否划算"（方向10 [4]）。

**F5. 规则和模型冲突怎么办？**
规则优先。RuleEngine 是唯一硬约束权威（方向10 [11][16][17][19][20]）；模型只能在规则允许的空间内做优化。若模型长期与规则冲突，说明规则阈值需要数据驱动地个体化（方向5 [8][18]），而不是让模型绕过规则。

**F6. 用户手动改了计划，要不要覆盖？**
不要直接覆盖。用户编辑是"目标承诺"的信号（方向3 [3]），也可能反映个体偏好；应把它作为 User State 更新与后续学习目标，并在下一次生成时尊重（方向3 [16][17]）。若编辑违反硬约束，再以"可读原因"提示而非静默覆盖（方向10 [20]）。

**F7. 怎么知道某条规则该不该上线？**
看证据强度（§4.2）。`强` 可直接上线；`中强` 上线但留开关与监控；`中` 先影子运行（只记录不拦截）；`理论` 只写进设计说明；`⚠` 不得单独作依据。上线后用 MRT/单被试设计评估改动效果（方向9 [13][23]）。

**F8. 冷启动的群体先验从哪来？**
来自文献报告的效应方向与量级（本目录各 RO），加上产品内早期用户数据。原则是"保守 + 快速个性化"（方向4 [30]；方向5 [18]），不要用群体均值直接预测个体（方向11 [21]）。

**F9. 数据里很多"没关页面"的超长耗时怎么办？**
不要统一截断。按个体、时段、任务做异常检测（方向4 [24]）；保留原始记录以便复算；用细粒度日志提高判定准确度（方向4 [22]）。

**F10. 怎么衡量"排程好不好"？**
至少三维：完成率（方向11 [14][15]）、预测误差（MAE/区间覆盖率，方向4 [33]）、以及状态代价（疲劳/情绪/放弃率，方向6 [6]；方向4 [39]）。只看完成率会漏掉"补偿控制"的隐性代价（方向6 [6]）。

**F11. 复习任务和普通任务怎么协调？**
复习任务视为普通任务的一种，占用时段和负荷配额（方向8 [19][22]）；其优先级由"预测保持概率"决定（方向8 [19][20]），并在 Scheduler 中与 `workload_redline`（方向5 [8]）共同约束。

**F12. 用户是夜猫子但必须早起上课怎么办？**
这是"社会时差"问题（方向7 [5]）。可做：晚间收尾/就寝提醒（方向7 [15][16]）、把高认知任务尽量排到其实际峰值窗口（方向7 [2][18]）、并记录晨间恢复感作为日状态（方向5 [18]）。不要强行按"早鸟模板"排程（方向7 [7][11]）。

**F13. 怎么防止系统"过度提醒"？**
降频 + 对事 + 效用阈值。反馈频率过高反而不利（方向9 [6][9][10]）；提醒时机非预期化（方向2 [17]）；用介入效用决定是否打扰（方向9 [30]）。

**F14. 测到用户压力高，要不要降难度？**
不能一概而论。压力方向不可预设（方向6 [7][8][9][11][20][21]）；应结合"威胁 vs 挑战"评价（方向6 [5]）与是否可控（方向6 [10]）来决定。多数情况下"给控制权 + 降低被评价感"比"直接降难度"更稳。

**F15. 怎么判断"拆解是否足够细"？**
三个停止条件：单次可完成（方向3 [4][5]）、单屏 ≤3~4 组块（方向3 [31]）、叶子到达可言语化的可执行单元（方向3 [25]）。再加一条边界：继续拆不会带来有用子目标/不会显著改善估时（方向3 [27][23]），且注意高不确定性时可能不该继续拆（方向3 [28]）。

**F16. 用户连续失败，系统该做什么？**
先做动机修复：子目标失败不得等同总目标失败（方向3 [21]）；再触发分级降级/换策略（方向9 [4]）；若属于"目标已不现实"，允许"目标脱离再投入"而非硬撑（方向9 [4]）。同时检查估时是否低估导致挫败（方向4 [39]）。

**F17. 为什么不能让 LLM 直接改 User State？**
因为状态要被规则、统计、调度共享，必须**可审计、可复现、可回溯来源**（方向9 [29]）。LLM 只能输出"建议的更新理由"或候选，由规则/统计落库；这与"LLM 不碰 DB"的项目约束一致（方向10 [8][10]）。

**F18. 上线后怎么持续验证这些文献结论？**
用在线实验：
- 排程/规则改动用 MRT 或单被试设计（方向9 [13][23]）。
- 自适应规则可用 SMART/DTR 框架逐步学习（方向9 [12][16][18][19]）。
- 同时监控"代价指标"（疲劳、情绪、放弃）以避免"完成率没变但状态变差"（方向6 [6]；方向4 [39]）。

**F19. 这些心理学结论可以直接抄进产品文案吗？**
不可以。文献给的是"统计上的平均效应与边界条件"，不是文案。文案生成交给 LLM（Harness），但必须受 RuleEngine 约束（R1/R14），并避免把"你不够自律"这类归因写进反馈（方向9 [6][7][8]）。

**F20. 为什么本目录反复强调"先观测、后固化"？**
因为任一单个方向都有"证据强度不足/摘要不可得/预印本/设备依赖"的条目（见 §4.2）。工程上稳妥的做法是：把强证据固化为规则，把中证据做成可开关的默认，把弱证据做成影子指标，用产品内数据再验证（方向9 [13]；方向4 [30]）。
