## 1. 目标

把既有设计（模型 / 状态评估 / 调度 / 规则 / 门控）排成可执行的实施顺序，并给出四件交付物：

1. **P0–P3 分阶段路线**：每阶段"做什么 / 不做什么 / 里程碑判据"，并明确"现在不该做什么"（§4.1）。
2. **埋点字段总表**：字段 / 类型 / 采集时机 / 支撑模型 / 阶段，作为事件表与特征派生的输入（§4.2）。
3. **风险假设与最小可行实验（MVE）**：R1–R10，每条"假设 → 若错的后果 → 实验 → 成功判据 → 依据"（§4.3）。
4. **比赛亮点**：8 条可讲、可被文献支撑的差异化点（§4.4）。

回答的问题：**先建什么、后建什么、怎么证明它有效、拿什么去比赛。**

## 4. 方案设计

### 4.1 P0–P3 分阶段路线（含"现在不该做什么"）

> 迁移自 `0-开发指导.md` 第五部分。**路线本身是【工程】排期**；括号内为文献依据。每阶段"里程碑判据"由原"目标/不做"显式化，属【工程】验收口径，**未新增文献**。

#### 4.1.1 P0（MVP，2–4 周）：确定性闭环，能跑通

**目标**：Goal → 规则拆解 → 规则排程 → 执行 → 反馈 → 规则重规划，全程可解释、可审计。

**做什么**
- 规则/模板拆解 + RuleEngine 硬约束（方向3 [1][9][31]）。
- Duration Predictor v0：理论时间 × 类型倍率 × 1.3（方向4 [10][11][29]）。
- Completion Predictor v0：规则分。
- Review Scheduler v0：固定扩展间隔 × 保持比例（方向8 [1][5]）。
- 注册问卷 + 每日打卡 + 任务后反馈（见 RO-3）。
- Replan v0：确定性规则 + per-user 冷却（见 RO-4 §4.10）。
- 埋点：§4.2 的 P0 字段。

**不做什么**
- 任何 ML、个性化模型、RL、LLM 自动化决策（LLM 只做拆解候选，且必须过 RuleEngine）。

**里程碑判据（【工程】）**
- 端到端闭环跑通：Goal → 规则拆解 → 规则排程 → 执行 → 反馈 → 规则重规划。
- 全程可解释、可审计（每个决策带 `reason_code`）。
- P0 埋点字段全部落库；硬决策中无 ML/LLM 参与。

#### 4.1.2 P1（4–8 周）：个体校准 + 统计模型

**做什么**
- `user_duration_factor`（M1 S1）；M2 个体 Logistic。
- M4a BKT（默认四参数 → 个体化学习率）（方向11 [9][11]）。
- M4b 精力/疲劳：EWMA + VAS。
- Review Scheduler S1：半衰期回归（方向8 [20]）。
- M5 规则 + 阈值校准；A/B 框架与 n-of-1 时间序列（方向9 [13]；方向9 [23]）。

**不做什么**
- 深度序列模型、bandit、复杂因果。

**里程碑判据（【工程】）**
- 上列 S1 模型/校准全部上线，且各有回退路径。
- A/B 与 n-of-1 时间序列框架可用，能跑出至少一次带对照的效果评估。
- 深度序列模型、bandit、复杂因果仍未上。

#### 4.1.3 P2（8–16 周）：预测升级 + 在线学习

**做什么**
- M1 S2：分位数 GBDT，输出 q80/q90（方向4 [32][33]）。
- M5 GBDT；M8 上下文 bandit（≥200 决策点）（方向9 [13]）。
- 难度自适应（M7 IRT/Elo）（方向5 [11]）。
- 微随机试验（MRT）校准提示/反馈策略（方向9 [13]）。

**不做什么**
- 全自动无人监督调整；所有自适应都要有 A/B 与回退。

**里程碑判据（【工程】）**
- M1 S2 / M5 GBDT / M8 bandit / M7 IRT-Elo / MRT 校准上线，且各自达到数据量门槛（门槛见 RO-2 §4.11）。
- 每个自适应组件都有 A/B 与回退开关；无"无人监督全自动调整"。

#### 4.1.4 P3（16 周+）：进阶与边界

**做什么**
- DKT/序列模型（≥1000 事件）（方向11 [10][12]）。
- Q-learning 重规划策略（≥200 决策点）（方向9 [14][18]）；DRL 复习调度（≥5000 事件）（方向8 [24]）。
- MPC 式滚动优化 + 鲁棒预算（方向9 [26][27]）。
- 多目标规划（成绩/睡眠/心理健康约束）（方向6 小结 4）。
- 可选可穿戴 HRV（仅作研究与双通道对照，谨慎）（方向6 [21]）。

**里程碑判据（【工程】）**
- DKT / Q-learning / DRL / MPC+鲁棒预算 / 多目标约束按数据门槛上线。
- 可穿戴 HRV 仅研究用途，不进产品决策闭环。

#### 4.1.5 现在不该做什么（P0 起全程适用）

> 迁移自 `0-开发指导.md` §5.5。

1. **不要上 EEG/fMRI/HRV 作为产品特征**：依赖实验室/设备，不可规模化（方向1 [18]；方向3 [32][33]；方向5 [25]）。
2. **不要用深度 RL 做主排程**：先规则+统计；RL 需海量数据且不可解释（方向8 [24]）。
3. **不要默认多模型堆叠（MoA）**：成本与省钱目标相反（方向10 [28]）。
4. **不要微调大模型**：成本高、迭代慢；先用结构化 Harness（方向10 小结）。
5. **不要设"通用固定每日上限"**：没有普适数值（方向5 小结 3）。
6. **不要高频打扰用户**：>1/3 反馈有害；降低频率更好（方向9 [6][9]）。
7. **不要用预期性固定提醒**：可能反成拖延锚点（方向2 [17]）。
8. **不要全量重规划**：默认局部修复，且有幅度上限与冷却（方向9 [25][28]）。
9. **不要一次排满 30 天**：用滚动时域，只锁定近 2 天（方向9 [26]）。
10. **不要过度采集隐私**：内容级键盘/摄像头一律不做。

### 4.4 比赛亮点（8 条）

> 迁移自 `0-开发指导.md` 第八部分。每条均有文献锚点，可作为比赛/答辩的差异化陈述。

1. **真闭环 + 因果实验**：不只做静态推荐，而是计划 → 执行 → 反馈 → 调整完整闭环，并用**微随机试验**（决策点随机化）估计组件因果效应（方向9 [13]）——比"跑个问卷"更有说服力。
2. **个性化记忆调度**：把间隔重复从固定算法升级为**半衰期回归 + 自适应遗忘曲线**，并按目标保持期缩放间隔（方向8 [5][19][20][23]）。
3. **估时的情绪管理**：不是追求无偏估时，而是**故意保守（q80）**以避免"比预期久"的负向情绪冲击（方向4 [39]）——一个反直觉但可被文献支撑的亮点。
4. **规则门控的 LLM Harness**：三层门控 + 语法约束解码 + 外部验证器，把"LLM 幻觉"从提示词问题变成**架构问题**（方向10 [11][19][25][27]）。
5. **计划稳定性与防震荡**：局部修复优先 + 调整幅度上限 + per-user 冷却 + 滚动时域（方向9 [24][25][26][28]），展示工程成熟度。
6. **零硬件状态感知**：用自评 VAS + 反应时变异 + 打字动力学估计疲劳，不依赖昂贵设备（方向1 [3][6][9]；方向5 [24]）。
7. **可解释、可审计**：规则/统计为主、LLM 为辅，所有决策有 `reason_code`（方向9 [3]；方向11 [9]）。
8. **多目标与善意设计**：成绩/睡眠/心理健康多目标；给用户控制权、非公开评价（方向6 小结 4；方向6 [5][10]）。
