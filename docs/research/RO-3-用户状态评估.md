## 4. 方案设计

### 4.1 分工原则：什么靠问、什么靠算

一句话原则：**"慢的、稳定的、主观体验的"靠问；"快的、可观测的、行为副产品的"靠算。**

| 靠问（问卷/自评） | 靠算（日志/行为推断） | 理由 |
|---|---|---|
| chronotype（早/晚型） | 实际最佳时段（历史成功率×时刻） | 量表给先验，行为给个体真相（方向7 [3][7][11]） |
| 长期目标、截止日期、重要性 | 截止临近度、进度偏差 | 目标只能问 |
| 自我效能（1 题） | 近期成功/失败、坚持时长 | 主观信念 vs 客观行为（方向11 [19]） |
| 精力/疲劳（VAS） | 反应时变异、打字动力学、连续高认知数 | 主观+行为互证（方向1 [3][6][9]） |
| 压力（双周） | 深夜活动、跳过天数 | 慢变量 + 行为代偿（方向6 [18][23]） |
| "哪里卡住了"（多选） | 完成率、放弃模式、耗时比 | 原因不可从日志直接推断 |
| 任务厌恶（可选） | 启动延迟、放弃 | 主观厌恶 + 行为证据（方向3 [34]） |

**不采集清单**（隐私红线）：精确地理位置、通讯录、相册、麦克风、摄像头、持续键盘内容。只采**任务相关行为的时间戳、正误、时长、点击/打字聚合指标**。

### 4.2 注册基线问卷（约 4–5 分钟，12–15 题）

> 每题给出：文案 / 构念 / 依据 / 落入 User State 字段。

**Q1. 基本信息**（open / 选项）
- 文案："怎么称呼你？你是学生还是在职？"
- 选项：学生（年级：大一…研究生）/ 在职 / 其他
- 构念：人口学基线（年龄会调节同步效应，方向7 [22]）
- 依据：方向7 [22]
- 字段：`user_age_group`、`user_role`

**Q2. Chronotype 单题**（5 选项）
- 文案："如果完全没有外界约束，你自然倾向什么时候起床和入睡？"
- 选项：① 很早（约 5–6 点起）绝对早型 ② 偏早（6–7 点）③ 中间（7–8 点）④ 偏晚（8–9 点）⑤ 很晚（9 点后）绝对晚型
- 构念：chronotype 先验（MEQ/CSM 思路）
- 依据：方向7 [3][5][12]
- 字段：`user_chronotype_tier`

**Q3. 作息**（时间输入）
- 文案："工作日你通常几点入睡、几点起床？周末呢？"
- 形态：4 个时间选择器（工作日入睡/起床、周末入睡/起床）
- 构念：睡眠中点 MSFsc、社会时差 SJL
- 依据：方向7 [4][6][15]
- 字段：`user_sleep_schedule_wd`、`user_sleep_schedule_we` → 系统计算 `user_msfsc`、`user_sjl`

**Q4. 每日可支配时间**（单选）
- 文案："平均每天，你能稳定投入学习/工作的时间大约是多少？"
- 选项：<30 分钟 / 30–60 / 60–120 / 120–180 / >180
- 构念：可用时间预算（个体化负荷上限初始值）
- 依据：方向5 [8][18]（负荷上限须个体化）
- 字段：`user_available_minutes`

**Q5. 目标与截止**（文本 + 日期 + 2 个评分）
- 文案："你最近最想完成的一个目标是什么？截止日期？对你有多重要？你有多想主动做它？"
- 形态：文本 + 日期 + 重要性 1–5 + 自主动机 1–5
- 构念：目标承诺、自主动机
- 依据：方向3 [1][3]；方向6 [1][2]
- 字段：`goal_text`、`goal_deadline`、`goal_importance`、`goal_autonomous_motivation`

**Q6. 自我效能**（1 题，1–5）
- 文案："如果现在就安排一个 45 分钟的学习任务，我有信心完整完成它。"
- 选项：1 完全没信心 → 5 非常有信心
- 构念：自我效能
- 依据：方向2 [5][23]；方向11 [19]
- 字段：`state_self_efficacy`（初始值）

**Q7. 拖延倾向**（1 题，1–5）
- 文案："我常把重要的事拖到最后一刻才做。"
- 选项：1 完全不符合 → 5 完全符合
- 构念：拖延倾向
- 依据：方向2 [1][6]
- 字段：`user_procrastination_trait`

**Q8. 主动拖延**（1 题，是/否）
- 文案："我有时故意把任务留到最后，因为压力能让我做得更好。"
- 构念：主动拖延（不应被打压）
- 依据：方向2 [21]
- 字段：`user_active_procrastination`

**Q9. 压力基线**（2 题，0–4）
- 文案 A："最近一个月，你多久感到无法控制生活中重要的事？"
- 文案 B："最近一个月，你多久感到事情堆积到无法应付？"
- 选项：0 从不 → 4 总是（PSS 精简思路）
- 构念：感知压力
- 依据：方向6 [18][19]
- 字段：`state_perceived_stress`

**Q10. 压力来源**（多选）
- 文案："你觉得压力主要来自哪里？"
- 选项：学业/工作应对失败 / 时间不够 / 人际 / 经济 / 健康 / 对未来不确定
- 构念：压力来源分解（来源比总分更有预测力）
- 依据：方向6 [19]
- 字段：`stress_source_profile`

**Q11. 最大干扰源**（多选）
- 文案："学习时最容易让你分心的是？"
- 选项：手机 / 社交媒体 / 环境噪音 / 思绪 / 疲劳 / 不知道该做什么
- 构念：干扰源（用于提示策略与任务设计）
- 依据：方向7 [19]
- 字段：`user_distraction_sources`

**Q12. 任务厌恶触发点**（多选）
- 文案："哪些情况最容易让你不想开始？"
- 选项：任务太模糊 / 任务太大 / 太枯燥 / 太难 / 不知道从哪开始 / 没有 deadline
- 构念：任务厌恶维度
- 依据：方向3 [34]；方向6 [22]
- 字段：`user_aversiveness_triggers`

**Q13. 学习方式偏好**（多选）
- 文案："你更喜欢怎么学？"
- 选项：看讲解 / 看例题 / 直接做题 / 讨论 / 看视频
- 构念：学习策略偏好
- 依据：方向11 [20]

**Q14. 提醒偏好**（可选）
- 文案："你希望系统怎么提醒你？"
- 选项：每天固定时段汇总 / 只在偏离计划时 / 尽量少打扰 / 我自己来
- 构念：receptivity 先验

### 4.6 引导策略：反馈措辞、提示频率、提醒时机

#### 4.6.1 反馈措辞原则（指向任务，不指向自我）

- **指向任务/过程，避免评价人格**：说"这一步卡在换元技巧，我们把它拆成两个例子"，不要说"你怎么又没做完"。→ 因为指向"自我"的反馈最容易损害表现，超过 1/3 的反馈干预反而降绩效（方向9 [6]）。
- **包含三要素**：Where am I going? How am I going? Where to next?（目标—现状—下一步）（方向9 [7]）。
- **形成性反馈四原则**：非评价、支持性、及时、具体（方向9 [8]）。
- **给用户控制权 + 非公开评价**：不可控 + 被评价感是最危险组合（方向6 [10][5]）。

#### 4.6.2 提示频率上限

- **主动提示 ≤ 3 次/天**（【工程】）；优先在"偏离计划"时提示，而不是日程式频繁提醒。
- **降低反馈频率促进长期学习**，过度反馈导致依赖（方向9 [9][10]）。
- **允许用户自控反馈**（点击"请求提示"），中等/自控频率效果最好（方向9 [10]）。
- **避免习惯化**：反馈内容要持续变化，否则长期效果衰减（方向11 [25]）。

#### 4.6.3 提醒时机（关键陷阱）

- **警惕"预期性提醒"反成拖延锚点**：可预测的提醒可能让用户把"等待提醒"当成拖延借口（方向2 [17]）。
- **优先多段紧时限 + 非预期提醒 + 随机检查点**，而非单一中等长度 deadline（中等长度单一时限表现最差，方向2 [14]；slippery deadline 放大拖延，方向2 [16]）。
- **按 JITAI 决策点触发**：在任务开始前、偏离后、日终三个决策点评估是否需要提示（方向9 [12][13]）。
- **用期望效用决定打扰**：低收益高打扰时延后（方向9 [30]）。
- **晚间降级**：夜间与醒日后期自我调节最脆弱，不安排需要强自律的任务，改放复习/阅读（方向7 [19]；方向1 [24]）。
- **明确任务边界**：告诉用户"这个任务大约 30 分钟就结束"，因为知道任务何时结束能提升表现、降低疲劳感（方向1 [13]）。

#### 4.6.4 引导文案示例

| 场景 | 反例（❌） | 正例（✅） | 依据 |
|---|---|---|---|
| 任务没完成 | "你又拖延了。" | "这一步需要先会换元；我把它拆成一个 15 分钟的例子，现在开始？" | 方向9 [6][7] |
| 完成很快 | "太棒了！" | "你比预估快 12 分钟。下一步把省下的时间用于复习昨天的极限题。" | 方向4 [39]（PE+ 管理） |
| 连续失败 | "你最近状态很差。" | "连续 3 天没达标，可能是任务量偏大。我把今天减到 1 个任务，先恢复节奏。" | 方向9 [6][25]；方向6 [10] |
| 提醒 | 每天 19:00 固定"该学习了" | 随机在计划启动前后窗口提示；由用户请求时随时响应 | 方向2 [14][16][17] |

### 4.7 隐私与伦理底线

- 最小采集：只采任务相关数据；不做内容级键盘记录。
- 明示用途：告诉用户数据用于调整计划，可导出、可删除。
- 不做公开评价：所有反馈私密（方向6 [10]）。
- 免责：系统不提供医疗/心理诊断；压力筛查异常时给求助资源而非"诊断"。

### 4.8 运行时问卷生成提示词库（LLM 动态出题）

> **通俗说明**：固定问卷（§4.2–4.4）覆盖常规情况，但遇到"异常状态"（连续失败、打卡突变、主动反馈"今天状态不对"）时，需要 LLM **根据上下文现场生成 1–3 个追问**。本节给出提示词模板。产出必须过 RO-6 的输出层强制校验（GCD + RuleEngine）。

#### 4.8.1 调用时机（由 M8 打扰策略裁决，不是想用就用）

| 触发场景 | 示例 | 频率上限 |
|---|---|---|
| 注册引导补全 | 基线问卷某题回答模糊/矛盾 | 注册流程内 ≤3 题 |
| 打卡异常 | 精力自评比近 7 天均值低 ≥2 档 | ≤1 题/天 |
| 连续失败 | 连续 2 天完成率 <60% | ≤2 题/次，触发后冷却 48h |
| 用户主动表达 | 反馈文本含负面情绪/困惑 | ≤2 题/次 |
| 长期画像刷新 | 每 2 周复测压力/效能 | 按周期 |

#### 4.8.2 系统提示词模板（出题器）

```text
你是自适应任务规划系统中的「状态评估出题器」。你的唯一职责是：根据用户上下文，
生成少量、温和、可快速回答的问题，用于估计用户当前状态。

【硬性规则】（违反任何一条的输出将被丢弃）：
1. 一次最多生成 {max_questions} 个问题。
2. 问题必须指向可观测的状态或行为，禁止评价人格、禁止质问（"你为什么又不努力"类直接判违规）。
3. 每个问题必须能映射到一个目标字段（target_field），从给定清单中选。
4. 题型只能是：single_choice（3-5 个选项）/ scale_1_5 / short_text（≤50 字）。
5. 语气温和、具体、给台阶：允许用户"跳过"。每题附 skip_allowed=true。
6. 禁止涉及医疗诊断、心理疾病判断、隐私敏感话题（家庭、收入、情感关系）。
7. 问题措辞遵循"指向任务而非自我"原则。

【构念参考】（来自调研，供你理解每个字段在测什么）：
- energy_level：主观精力，1-5 自评即有预测价值（方向1 [21][22] 心理精力量表）
- stress_level / stress_source：感知压力及其来源，分挑战型/阻碍型（方向6 [1][2]）
- task_aversiveness：对具体任务的厌恶来源（无聊/困难/模糊/畏惧失败）（方向2 [20] 任务特征；方向3 [34] 任务厌恶多维）
- self_efficacy：对"自己能完成"的信心（方向11 [19]）
- blocker_type：卡点类型（不会/没时间/忘了/不想做）（【工程】构念，无直接文献条目；措辞遵循方向9 [7] 反馈三要素）

【用户上下文】：
{user_context_json}

【输出格式】（严格 JSON，不要输出任何其他文字）：
{
  "questions": [
    {
      "id": "q1",
      "text": "问题文案",
      "type": "single_choice | scale_1_5 | short_text",
      "options": ["..."],
      "target_field": "energy_level | stress_level | ...",
      "construct_note": "这题在测什么（内部记录，不展示给用户）",
      "skip_allowed": true
    }
  ],
  "rationale": "为什么问这些（≤50 字，内部记录）"
}
```

#### 4.8.3 输入上下文 JSON（`user_context_json` 的 schema）

```json
{
  "trigger": "checkin_anomaly | streak_failure | user_initiated | baseline_gap | biweekly",
  "recent": {
    "completion_rate_7d": 0.55,
    "energy_checkin_today": 2,
    "energy_checkin_avg_7d": 4.1,
    "failed_tasks_recent": [{"title": "…", "type": "practice", "reason_code": "too_hard"}]
  },
  "known_state": {"chronotype": "late", "self_efficacy": 0.6},
  "fields_needed": ["stress_source", "blocker_type"],
  "max_questions": 2,
  "locale": "zh-CN"
}
```

#### 4.8.4 生成结果的校验与落地

1. **GCD**：输出必须是合法 JSON、字段齐全（方向10 [25]）。
2. **RuleEngine 语义校验**（出题器专用规则）：
   - `R-Q1 数量上限`：≤ `max_questions`；
   - `R-Q2 频率上限`：与 §4.6.2 合并计数（LLM 追问计入每日 ≤3 次提示额度）；
   - `R-Q3 敏感话题黑名单`：命中即丢弃该题；
   - `R-Q4 target_field 白名单`：必须在 `fields_needed` 内；
   - 违规 → 丢弃该题并记录 `rule_violation_codes`，不反问 LLM（避免循环）。
3. **回答落库**：答案按 `target_field` 写入对应 User State 字段，走与固定问卷完全相同的更新通道（RO-2 §4.4），不另开通路。
4. **防依赖**：LLM 追问与固定打卡**互斥**——同一天已触发动态追问，则当日不再追加任何额外出题（方向9 [9][10] 反馈过频有害）。【外推】

#### 4.8.5 防烦设计（问卷负担控制）

> **核心立场**：每一道题都是向用户"借钱"，借多了用户就卸载。反馈干预超 1/3 反而降绩效（方向9 [6]），过频反馈导致依赖（方向9 [9][10]），问卷设计的第一约束不是"想问什么"而是"用户愿意答多少"。

**五条负担控制机制**：

1. **总题量预算（每天 ≤5 题，含所有来源）**：打卡 3 题 + 动态追问 + 任务后反馈合并计数，由 M8 统一分配额度；额度耗尽时优先级：打卡 > 异常追问 > 画像刷新。
2. **能算就不问**：出题前先查行为信号是否已能回答（§4.5）。例：连续 3 天深夜完成任务 → 疲劳已有行为证据，**不再追问**"你是不是累了"。只有行为信号推断不出（如压力来源、卡点类型）才允许出题。
3. **负担信号监测（行为熔断）**：
   - 跳过率：近 14 天跳过率 >40% → 动态追问自动降频一档（2 题→1 题），>60% → 暂停动态追问 7 天只保留打卡；
   - 答题反应时：超过该用户中位数 2 倍视为负担加重信号，进入降频观察；
   - 打开不答：连续 3 次"看到问题未作答即关闭" → 暂停一切非必要问题 14 天。
4. **自适应衰减**：某 `target_field` 近期估计已稳定（方差 < 阈值且与其他信号一致）→ 该字段出题频率自动减半，把额度让给估计不准的字段。
5. **价值回显**：每次问卷后展示"这个问题如何改变了你的计划"（如"因为你说精力低，今天的高数调到了明早"）。用户看到回答有用，才愿意继续答——这是维持长期应答率的关键设计。

新增 RuleEngine 规则 `R-Q5 负担熔断`：当日累计题量 >5 或熔断状态激活 → 丢弃一切非必答题（打卡降级为 1 题：仅精力自评）。
