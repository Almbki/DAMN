## 4. 方案设计

### 4.0 模型全景与通用约定

#### 4.0.1 模型全景与依赖关系

```
第一层（用户状态，所有计划的输入）
  M4 User State Estimator
      ├─ M4a Skill/Mastery（技能掌握概率，BKT）
      ├─ M4b Energy/Fatigue（精力/疲劳）
      ├─ M4c Self-efficacy（自我效能）
      └─ M4d Stress（压力，慢变量）

第二层（预测，决定任务怎么排）
  M1 Duration Predictor         预测"这个任务要多久"
  M2 Completion Predictor       预测"今天这个任务做不做得完"
  M7 Task Difficulty Estimator  估计"任务到底多难"
  M3 Review Scheduler           估计"什么时候该复习才不会忘"

第三层（决策，决定系统怎么动）
  M5 Replan Trigger             判断"计划跑偏没有，要不要重排"
  M6 LLM Router                 判断"这一步要不要叫大模型"
  M8 Prompt/Interruption Policy 判断"现在该不该打扰用户"
```

**依赖方向必须单向**：M4 先更新 → M1/M2/M3/M7 用 M4 → M5/M6/M8 用前面全部。**禁止 M4 反过来读 M5 的输出**，否则循环依赖（对应项目架构"API → Application → Domain/Core → Infra"的单向依赖）。

> **依据**：状态估计驱动个体化调整有效（方向11 [22] 元分析 g=0.42；方向11 [24] 个性化自适应框架）；状态估计→规则触发的难度调整是成熟范式（方向5 [25]）；闭环需要"估计→差异→调整"结构（方向9 [3]）。这属于设计范式的【文献】支持，模块划分本身是【工程】。

#### 4.0.2 通用约定：特征命名与类型

| 前缀 | 含义 | 例子 |
|---|---|---|
| `task_*` | 任务本身属性（来自 LLM/规则/用户输入） | `task_type`、`task_difficulty_prior` |
| `item_*` | 知识点/题目（用于复习） | `item_id`、`item_difficulty` |
| `user_*` | 用户稳定特征（问卷/长期统计） | `user_duration_factor`（用户耗时倍率） |
| `state_*` | 用户时变状态（模型估计） | `state_fatigue`、`state_skill_mastery` |
| `log_*` | 行为日志派生 | `log_completion_rate_7d`、`log_first_action_delay_min` |
| `sched_*` | 排程上下文 | `sched_hour`、`sched_day_of_week` |
| `pred_*` | 模型输出 | `pred_duration_q50`、`pred_recall_prob` |

类型只用 4 种：`float`（数值）、`int`（计数）、`bool`（是否）、`enum`（枚举，如 `task_type ∈ {concept, example, practice, review, project}`）。所有概率统一 0–1，所有自评统一 1–5，时间段统一 0–23 整数小时。

#### 4.0.3 通用约定：冷启动三阶段

| 阶段 | 触发条件 | 做法 | 目的 | 依据 |
|---|---|---|---|---|
| **S0 群体先验** | 新用户，0 条数据 | 规则 + 群体中位数 | 能用、不崩 | 方向4 [29] |
| **S1 个体校准** | 同一用户同类任务 ≥ 20 条（【工程】） | 个体倍率/简单回归 | 比群体准 | 方向4 [30] |
| **S2 数据驱动** | 全量任务 ≥ 300 条 或 同类 ≥ 100 条（【工程】） | GBDT / 序列模型 / 层级贝叶斯 | 逼近上限 | 方向4 [32][33][36]；方向11 [9][10][12] |

> **依据**：冷启动/小样本阶段简单可解释模型（历史均值、分组倍率）已足够且更稳健（方向4 [29]）；数据丰富后 ML 明显优于历史均值基线，且要输出不确定性（方向4 [32][33][36]）；小数据选 BKT、大数据选深度模型（方向11 [9][10][12]）。**具体样本量数字全部是【工程】默认值。**

#### 4.0.4 通用约定：统一升级/回退触发

```
升级到 S1：n_same_type >= 20 且 连续 7 天有数据
升级到 S2：n_total >= 300 且 S1 相对 S0 的误差下降 >= 10%
回退：新模型相对旧模型在滚动 14 天窗口误差变差 > 10% → 自动回退
```

**效果阈值**（【工程】待校准）：耗时 MAE 相对基线下降 ≥ 15%；完成率 AUC 相对基线提升 ≥ 5%；复习回忆预测 Brier 分数下降 ≥ 10%。未达标不上线（方向4 [32] 支持"要输出不确定性"；方向10 [4] 支持"先离线验证再上线"）。

#### 4.0.5 通用约定：统一输出规范

- 分类/概率模型：输出 `prob + CI80`。
- 回归模型（耗时）：**必须输出分位数**，排程默认用 `q80` 而非 `q50`（见 RO-4；依据方向4 [39]）。
- 决策模型：输出 `decision + confidence + reason_code`（可解释、可审计）。

### 4.1 M1 Duration Predictor（任务耗时预测）

**要解决**：这个任务这个人大概要多久？（Scheduler 的基础输入。）

#### 4.1.1 依据什么建立

- **为什么选它**：耗时是排程容量的基本单位；文献支持"任务侧（类型/复杂度/清晰度）+ 个体侧（经验/能力/速度偏好）共同决定耗时"（方向4 综合结论；方向4 [4][19][20][35][39]）。
- **为什么用"理论时间 × 个体倍率"起步**：KLM/GOMS 给出"熟练无错"的理论下限（方向4 [10][11]），把它当作可解释的锚点；个体差异再乘一个用户级倍率（方向4 [19][20][21]）。这是冷启动阶段最稳、可手算、可审计的形态。
- **为什么不用更深的 ML（S0/S1）**：小样本下 ML 不稳定且不可解释（方向4 [29] 综述：简单模型在小数据下足够）；且文献指出的 ML 优势条件是**特征丰富、样本充足**（方向4 [33][32][36]）。
- **为什么必须输出分位数**：估时误差反噬情绪——比预期久（PE−）恶化情绪与投入，比预期短（PE+）改善（方向4 [39]）。因此排程要用保守上界。
- **为什么禁止固定乐观系数**：低估并非普适规律，工程/管理常见低估、心理学未必，短任务常高估（方向4 [3][8]）。

#### 4.1.2 完整参数定义

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 任务类型 | `task_type` | enum | `concept/example/practice/review/project` | 任务生成时由 LLM/模板写死 | 任务创建时（不变） | `practice`（默认） |
| 任务先验难度 | `task_difficulty_prior` | float（1–5 档） | 1–5 | LLM 生成 + 人工规则校验 | 任务创建时 | `3`（中等） |
| 任务描述清晰度 | `task_clarity` | float（0–1 概率/评分） | 0–1 | LLM 对任务描述打分 | 任务创建时 | `0.5` |
| 任务理论最少耗时 | `task_theoretical_min` | float（分钟） | ≥0 | 系统按 KLM/GOMS 近似计算 | 任务创建时 | 无 → 用同 `task_type` 历史中位数 |
| 技能掌握概率 | `state_skill_mastery` | float（0–1） | 0–1 | M4a 输出 | 每次作答后 | `0.3`（群体先验） |
| 该技能历史练习次数 | `log_practice_count` | int（次） | ≥0 | 任务/作答日志聚合 | 每次完成后 +1 | `0` |
| 用户耗时倍率 | `user_duration_factor` | float（无量纲，实际/理论） | >0，典型 0.5–3 | M1 自身历史校准（按 `task_type` 分桶） | 每次完成后滚动更新 | `1.3`（群体保守倍率，【工程】） |
| 疲劳状态 | `state_fatigue` | float（0–1） | 0–1 | M4b 输出 | 分钟级/每任务 | `0`（不调整） |
| 精力状态 | `state_energy` | float（0–1） | 0–1 | M4b 输出（源自自评 VAS） | 每日打卡 + 任务后 | `0.5`（中性） |
| 排程时刻 | `sched_hour` | int（小时） | 0–23 | 排程上下文 | 排程时 | 当前时刻所在小时 |
| 用户节律型分档 | `user_chronotype_tier` | enum | `early/mid/late` | 注册问卷（RO-3 Q2） | 注册时 + 可重测 | `mid` |
| 近 3 天负荷 | `log_recent_load_3d` | float（分钟） | ≥0 | 日志聚合 | 每日 | `0` |
| 当日任务序位 | `log_session_position` | int（第几个） | ≥1 | 当日执行日志 | 每任务 | `1` |

#### 4.1.2b 参数计算方式

> **符号约定**：`i` = 历史任务/事件下标；`N` = 窗口大小；`median(·)` = 中位数；`quantile(·,p)` = p 分位数；`clamp(x,a,b)` = 截断到 [a,b]。**原始输入**=直接来自问卷/日志，不做计算；**派生参数**=必须按公式计算。

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `task_type` | 原始 | 任务生成时由 LLM/模板写死，不做计算 | 【工程】字段 |
| `task_difficulty_prior` | 原始 | LLM 打分（1–5）+ 人工规则校验，不做计算 | 【工程】 |
| `task_clarity` | 原始 | LLM 对任务描述打分（0–1）；LLM 不可用时用规则 `1 − 命中含糊动词数/3` | 【工程】 |
| `task_theoretical_min` | 派生 | KLM 加和：`(Σ_op t_op)/60`，操作常数见下式 | 方向4 [10][11] |
| `state_skill_mastery` | 派生（跨模型） | 由 M4a 输出，公式见 §4.4.1 | 方向11 [9][11] |
| `log_practice_count` | 派生 | `|{已完成任务 t : skill(t)=skill_id}|`（全历史累计） | 方向4 [15] |
| `user_duration_factor` | 派生 | 见下式：按 `task_type` 分桶的 `median(actual/theoretical)`，窗口 N=30 | 方向4 [20][21]；N 为【工程】 |
| `state_fatigue` / `state_energy` | 派生（跨模型） | 由 M4b 输出，公式见 §4.4.2 | 方向1 [3][6][7] |
| `sched_hour` | 原始 | 排程上下文直接给出（0–23），不做计算 | 【工程】 |
| `user_chronotype_tier` | 原始 | 注册问卷 Q2 直接映射 `early/mid/late`，不做计算 | 方向7 [3] |
| `log_recent_load_3d` | 派生 | `Σ_{t∈今天与前2天} alloc_min(t)`（alloc 为该任务分配给用户的时长） | 【工程】 |
| `log_session_position` | 派生 | `1 + |{今天已开始的任务}|` | 【工程】 |
| `pred_duration_q50/q80/q90` | 派生（模型输出） | 见下式 S0/S1；S2 由 GBDT 直接输出 | 方向4 [10][11][32][39] |

**主公式**：

```text
# 1) 理论最少耗时（KLM；方向4 [10] 的操作常数）
task_theoretical_min = (Σ_op t_op) / 60        # 秒 → 分钟
    t_K=0.2s 键盘, t_P=1.1s 指向, t_H=0.4s 归位, t_M=1.35s 心理准备, t_R=1.1s 系统响应

# 2) 用户耗时倍率（按 task_type 分桶；只取已完成且 theoretical_min>0 的任务）
ratio_i = actual_min_i / theoretical_min_i
user_duration_factor(type) = median(ratio_i),  i ∈ 该用户该 type 桶内最近 N=30 条   # N【工程】
    若桶内有效条数 < 3 → 1.3（群体保守倍率，【工程】）
    若 theoretical_min 缺失 → 分母改用该 type 历史 actual 的中位数

# 3) 单任务点估计（S0/S1）
base            = theoretical_min × type_multiplier
    type_multiplier【工程】：concept 1.2 / example 1.1 / practice 1.3 / review 0.6 / project 1.8
fatigue_factor  = 1 + 0.30 × (state_fatigue − 0.5)      # 系数 0.30【工程】
energy_factor   = 1 − 0.20 × (state_energy  − 0.5)      # 系数 0.20【工程】
hour_factor     = 1.15 当 task_type∈{concept,practice,project} 且 sched_hour 不在个人峰值窗口，否则 1.00   # 【工程】
pred_duration_q50 = base × user_duration_factor × fatigue_factor × energy_factor × hour_factor

# 4) 分位数（S1）
pred_duration_q80 = theoretical_min × quantile(ratio_i, 0.80) × 调整项
pred_duration_q90 = theoretical_min × quantile(ratio_i, 0.90) × 调整项
    若有效条数 < 20 → 退化用展宽系数：q80 = q50 × 1.25，q90 = q50 × 1.50   # 20 与系数均【工程】
    排程默认用 q80（RO-4 §4.8；方向4 [39]）
```

#### 4.1.3 冷启动 / 升级 / 降级（本模型内）

| 阶段 | 形态 | 做法 |
|---|---|---|
| **S0** | 规则 | `task_theoretical_min × 类型倍率 × 1.3`（1.3 为保守系数【工程】） |
| **S1** | 统计 | 用户历史 `实际/理论` 的**中位数** × 当期理论时间，按 `task_type` 分桶 |
| **S2** | ML | 分位数 GBDT（LightGBM quantile）预测 q50/q80/q90 |
| **降级 S2→S1** | 统计 | 回落个体耗时倍率中位数 |
| **降级 S1→S0** | 规则 | `理论时间 × 1.3`（群体保守倍率） |
| **缺特征兜底** | — | 无历史 → `user_duration_factor=1.3`；无疲劳数据 → 疲劳项置 0 |

**升级触发**：S1：同类任务 ≥20 条；S2：全量 ≥300 条且相对 S0 的 MAE ↓ ≥15%（离线留出法验证后上线）。**门槛为【工程】。**
**降级触发**：滚动 14 天窗口误差比旧模型变差 >10% → 回退；滚动 90 天有效样本跌破升级门槛 50% → 收缩加权（见 §4.11.2）。

#### 4.1.4 输出形式与消费方

- **输出**：`pred_duration_q50`、`pred_duration_q80`、`pred_duration_q90` + `pred_duration_interval`。
- **消费方**：RO-4 Scheduler（默认用 `q80` 做容量校验）；RO-5 RuleEngine（R9 估时保守输出校验）；RO-2 M5（耗时偏差特征）。

**验收指标建议**（离线/线上）：MAE、区间覆盖率（实际落在预测区间内的比例）、`%over/%under/%within`（参照方向4 [33] 的度量），以及**预测误差对情绪的影响**监控（方向4 [39]）。

**局限与风险**：疲劳项只作温和调整（方向4 [37] 为间接证据）；不要内置固定乐观系数（方向4 [3] 偏差方向因领域而异）。

#### 4.1.5 端到端算例：从原始日志到 q50/q80（手算）

> 虚构用户 U001（晚型，峰值窗口 16:00–22:00），`task_type=practice` 的 5 条历史已完成任务：

| i | `task_theoretical_min`（KLM） | `actual_min`（日志） | `ratio_i = actual/theoretical` |
|---|---|---|---|
| 1 | 20 | 34 | 1.70 |
| 2 | 25 | 41 | 1.64 |
| 3 | 15 | 28 | 1.87 |
| 4 | 30 | 48 | 1.60 |
| 5 | 25 | 43 | 1.72 |

**步骤 1：`log_practice_count`** = 5（全历史累计，本例同桶 5 条）。

**步骤 2：`user_duration_factor(practice)`**（窗口 N=30）：
```
ratio 排序 = {1.60, 1.64, 1.70, 1.72, 1.87}
有效条数 = 5 ≥ 3 → 取中位数
user_duration_factor = median = 1.70
```

**步骤 3：新任务估时**。新任务：`task_type=practice`，`task_theoretical_min=25`，`state_fatigue=0.6`，`state_energy=0.4`，`sched_hour=10`（10:00 不在晚型峰值窗口）：
```
base           = 25 × 1.3( practice ) = 32.5
fatigue_factor = 1 + 0.30×(0.6−0.5)   = 1.03
energy_factor  = 1 − 0.20×(0.4−0.5)   = 1.02
hour_factor    = 1.15（高认知类型 + 非峰值时段）
pred_duration_q50 = 32.5 × 1.70 × 1.03 × 1.02 × 1.15
                  = 32.5 × 1.70 = 55.25
                  → 55.25 × 1.03 = 56.9075
                  → 56.9075 × 1.02 = 58.0457
                  → 58.0457 × 1.15 = 66.75 ≈ 66.8 分钟
```

**步骤 4：分位数**。有效条数 5 < 20 → 用展宽系数退化：
```
pred_duration_q80 = 66.8 × 1.25 = 83.5 分钟
pred_duration_q90 = 66.8 × 1.50 = 100.2 分钟
（若改用 5 点直接分位：quantile(ratio,0.80)=1.786 → q80≈32.5×1.786×1.03×1.02×1.15≈70.2 分钟；
  样本不足 20 时按【工程】规则一律用展宽系数，避免小样本分位不稳）
```

**步骤 5：排程使用**。RO-4 Scheduler 取 `pred_duration_q80 = 83.5` 分钟做当日容量校验（不用 q50），把"不确定性"翻译成时间缓冲（方向4 [39]）。

> 全部自定数值：N=30、最小 3 条、保守倍率 1.3、type_multiplier、疲劳 0.30 / 精力 0.20、hour_factor 1.15、展宽 1.25/1.50、样本阈值 20 —— 均为 **【工程】**，需上线校准。

### 4.2 M2 Completion Predictor（完成概率预测）

**要解决**：今天排给用户的这个任务，他完成的概率多大？（决定任务是否要缩小、提前、或换时段。）

#### 4.2.1 依据什么建立

- **为什么选它**：完成率是最易采、最强的预测源（方向11 [14][15][19]）；拖延可参数化、历史延迟可预测未来（方向2 [1][12][16][23]）。
- **为什么用规则分起步**：冷启动没有个体数据，用群体先验 + 可解释规则最稳（方向4 [29] 的小数据原则）；且完成概率是 Scheduler 的容量决策输入，必须可解释。
- **为什么输入含任务厌恶/清晰度**：任务厌恶、自我效能、deadline 距离是拖延主预测因子（方向2 小结；方向3 [34]）；角色模糊是最强负相关（方向6 [22]）。
- **为什么不用更深模型**：个体数据通常先攒到几十条完成/失败事件，逻辑回归（特征 ≤8）足够防过拟合；GBDT 仅在 S2。
- **为什么区分主动拖延**：主动拖延者可能有策略并表现更好，不该被打压（方向2 [21]）。

#### 4.2.2 完整参数定义

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 任务厌恶度 | `task_aversiveness` | float（1–5 档） | 1–5 | LLM 评分 + 用户可选反馈 | 任务创建/反馈时 | `3`（中性） |
| 任务描述清晰度 | `task_clarity` | float（0–1） | 0–1 | LLM | 任务创建时 | `0.5` |
| 任务先验难度 | `task_difficulty_prior` | float（1–5 档） | 1–5 | LLM | 任务创建时 | `3` |
| 技能掌握概率 | `state_skill_mastery` | float（0–1） | 0–1 | M4a | 每次作答后 | `0.3` |
| 距截止天数 | `sched_deadline_distance_d` | float（天） | ≥0 | 排程上下文 | 每日 | 无 deadline → 置大值（如 999） |
| 上次启动延迟 | `log_onset_delay_prev` | float（分钟） | ≥0 | 日志（计划开始→实际开始） | 每任务 | `0` |
| 近 7 天完成率 | `log_completion_rate_7d` | float（0–1） | 0–1 | 日志聚合 | 每日 | 群体先验 `0.7` |
| 自我效能 | `state_self_efficacy` | float（0–1） | 0–1 | M4c（源自单题自评） | 任务成败后 EWMA | 注册问卷单题分 |
| 疲劳状态 | `state_fatigue` | float（0–1） | 0–1 | M4b | 分钟级/每任务 | `0` |
| 排程时刻 | `sched_hour` | int（小时） | 0–23 | 排程 | 排程时 | 当前小时 |
| 连续完成天数 | `log_streak` | int（天） | ≥0 | 日志 | 每日 | `0` |
| 主动拖延标记 | `user_active_procrastination` | bool | true/false | 注册问卷（RO-3 Q8） | 注册时 | `false` |
| 今日计划总量 | `sched_today_load_planned` | float（分钟） | ≥0 | 排程 | 每日 | `0` |

#### 4.2.2b 参数计算方式

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `task_aversiveness` | 原始 | LLM 评分（1–5）+ 用户可选反馈，不做计算 | 方向3 [34]；方向2 [20] |
| `task_clarity` | 原始 | LLM 打分 0–1（同 §4.1.2b） | 【工程】 |
| `task_difficulty_prior` | 原始 | LLM 打分 1–5 | 【工程】 |
| `state_skill_mastery` | 派生（跨模型） | 见 §4.4.1 | 方向11 [9] |
| `sched_deadline_distance_d` | 派生 | `(goal_deadline − today).days`；无 deadline → 999 | 【工程】 |
| `log_onset_delay_prev` | 派生 | `actual_start_prev − planned_start_prev`（分钟）；无上一条 → 0 | 方向2 [18] |
| `log_completion_rate_7d` | 派生 | `completed_7d / planned_7d`；`planned_7d=0` → 0.7 | 方向11 [19] |
| `state_self_efficacy` | 派生（跨模型） | 见 §4.4.3 | 方向2 [5][23]；方向11 [19] |
| `state_fatigue` | 派生（跨模型） | 见 §4.4.2 | 方向1 [3] |
| `sched_hour` | 原始 | 排程上下文 | 【工程】 |
| `log_streak` | 派生 | 结尾连续满足"当日 `completion_rate_day ≥ 0.8`"的天数；中断即 0 | 【工程】 |
| `user_active_procrastination` | 原始 | 注册问卷 Q8 直接映射 bool | 方向2 [21] |
| `sched_today_load_planned` | 派生 | `Σ alloc_min(今天全部计划任务)` | 【工程】 |
| `pred_completion_prob` | 派生（模型输出） | S0 规则分 / S1 逻辑回归，见下式 | 方向2 小结；方向11 [19] |

**主公式**：

```text
# S0 规则分（全部输入先归一化到 0–1）
d = (task_difficulty_prior − 1)/4 ;  a = (task_aversiveness − 1)/4 ;  c = task_clarity
p0 = clamp(0.90 − 0.10×d − 0.15×a + 0.10×c, 0.05, 0.95)     # 系数【工程】

# S1 个体逻辑回归（特征 ≤ 8）
x = [d, a, c, state_skill_mastery, min(sched_deadline_distance_d,90)/90,
     log_onset_delay_prev/60, log_completion_rate_7d, state_self_efficacy]
z = w0 + Σ w_k x_k ;  p = 1 / (1 + e^(−z))
    权重 w 由该用户"完成/失败"事件拟合（L2 正则 λ=1.0【工程】）
    校准：可选 Platt / isotonic，使预测概率与真实频率一致（【工程】）

# 输出
pred_completion_prob = p（分类），CI80 = Wilson 区间（【工程】方法）
```

#### 4.2.3 冷启动 / 升级 / 降级

| 阶段 | 形态 | 做法 |
|---|---|---|
| **S0** | 规则 | `base 0.9 − 0.1×难度 − 0.15×厌恶 + 0.1×清晰度`，裁剪到 [0.05, 0.95]（【工程】） |
| **S1** | 统计/经典 | 个体 Logistic 回归（特征 ≤ 8 个，防过拟合） |
| **S2** | 经典→ML | GBDT / 校准后的逻辑回归 |
| **降级 S2→S1** | 统计 | 分层基准率（按 `task_type` 分组的历史完成率） |
| **降级 S1→S0** | 规则 | 群体完成率先验 `0.7` |
| **缺特征兜底** | — | 无历史 → 先验 0.7；无自我效能 → 用注册问卷单题分 |

**升级触发**：S1：完成/失败事件 ≥50；S2：≥300 且 AUC 相对基线 ↑ ≥5%（离线验证）。**【工程】**
**降级触发**：同 §4.0.4；滚动 90 天样本 < 门槛 50% → 收缩加权。

#### 4.2.4 输出形式与消费方

- **输出**：`pred_completion_prob` + CI80。
- **消费方**：RO-4 Scheduler（`<0.5` → 自动拆小/换时段/提前；`<0.3` → 触发 LLM Harness 生成"启动助推"与情绪拆解，方向2 [22]）；RO-2 M5（完成概率特征）。

**依据小结**：拖延可参数化（方向2 [1][12][16][23]）；主预测因子（方向2 小结 2）；SRL 元分析最强预测（方向11 [19]）；role ambiguity 最强负相关（方向6 [22]）。

### 4.3 M3 Review Scheduler（复习调度 / 记忆保持）

**要解决**：一个知识点/题目，什么时候再复习，才能记得住又不过度复习？

#### 4.3.1 依据什么建立

- **为什么选它**：间隔效应与测试效应是学习方向最强证据（方向8 [1][2][6][9][10][11]）；最佳间隔随"目标保持期"缩放，而非固定（方向8 [1][5]）。
- **为什么用固定扩展间隔起步**：冷启动无个体回忆数据，用"保持期 × 比例"的规则表最简单可解释（方向8 [1][5]）。
- **为什么用 HLR（半衰期回归）而非自研**：HLR 是可工程复用的成熟算法（方向8 [20]）；先复用、别自研。
- **为什么不用深度 RL 做复习调度**：个体遗忘速度存在稳定差异，群体幂律不可当个体参数（方向8 [13][16][17]）；DRL 需 ≥5000 事件且须证明不劣于 HLR（方向8 [24]，【工程】门槛）。
- **为什么先测后看**：提取练习（先测再学）优于重复阅读（方向8 [2][6]）。

#### 4.3.2 完整参数定义

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 知识点/题目 ID | `item_id` | str | — | 复习库 | 不变 | — |
| 知识点难度 | `item_difficulty` | float（1–5 档） | 1–5 | 任务侧标注 | 任务创建时 | `3` |
| 已复习次数 | `log_review_count` | int（次） | ≥0 | 复习日志 | 每次复习 +1 | `0` |
| 上次复习时间 | `log_last_review_ts` | datetime | — | 复习日志 | 每次复习 | 无 → 视为首次复习 |
| 上次回忆是否成功 | `log_last_recall_ok` | bool | true/false | 复习日志 | 每次复习 | 无 → 视为未测（按首次） |
| 连续回忆成功次数 | `log_recall_streak` | int（次） | ≥0 | 复习日志 | 每次复习 | `0` |
| 回忆反应时 | `log_response_time_sec` | float（秒） | ≥0 | 复习日志 | 每次复习 | 该 item 历史中位数 |
| 技能掌握概率 | `state_skill_mastery` | float（0–1） | 0–1 | M4a | 每次作答后 | `0.3` |
| 用户遗忘速率 | `user_forgetting_rate` | float（无量纲，半衰期缩放） | >0 | M3 个体参数（HLR 拟合） | 每次复习滚动 | 群体中位数半衰期 |
| 目标保持期 | `goal_retention_interval_d` | float（天） | ≥1 | 目标设定（距考试/目标） | 目标变更时 | 默认 30 天【工程】 |
| 复习积压数 | `log_review_backlog` | int（待复习条数） | ≥0 | 复习队列 | 每日 | `0` |
| 排程时刻 | `sched_hour` | int（小时） | 0–23 | 排程 | 排程时 | 当前小时 |

#### 4.3.2b 参数计算方式

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `item_id` | 原始 | 复习库主键 | 【工程】 |
| `item_difficulty` | 原始 | 任务侧标注 1–5，不做计算 | 方向8 [20] |
| `log_review_count` | 派生 | `|{复习事件 e : item(e)=item_id}|`（含本次前） | 【工程】 |
| `log_last_review_ts` | 原始 | 复习日志时间戳 | 【工程】 |
| `log_last_recall_ok` | 原始 | 上次作答对/错（bool） | 方向8 [6] |
| `log_recall_streak` | 派生 | 截至上次复习、结尾连续 `recall_ok=true` 的次数 | 【工程】 |
| `log_response_time_sec` | 原始 | 作答反应时（秒） | 方向8 [20] |
| `state_skill_mastery` | 派生（跨模型） | 见 §4.4.1 | 方向11 [9] |
| `user_forgetting_rate` | 派生 | `1 / half_life_days`（HLR 拟合，见下式） | 方向8 [16][17][20][23] |
| `goal_retention_interval_d` | 原始 | 目标设定（距考试/目标的期望保持期），不做计算 | 方向8 [5] |
| `log_review_backlog` | 派生 | `|{item : next_review_at(item) ≤ today}|` | 方向8 [26] |
| `sched_hour` | 原始 | 排程上下文 | 【工程】 |
| `pred_recall_prob` / `next_review_at` | 派生（模型输出） | 见下式 | 方向8 [20][22] |

**主公式**：

```text
# S0 固定扩展间隔（规则）
interval_1 = 1 天 ;  interval_n = interval_{n−1} × 1.8                  # 倍率【外推】
interval_n ← interval_n × clamp(goal_retention_interval_d / 30, 0.5, 4.0)   # 保持期缩放【外推】

# S1 半衰期回归 HLR（Settles & Meeder 2016；方向8 [20]）
half_life_days = 2 ^ ( a + b1·ln(1+log_review_count) + b2·last_recall_ok
                         + b3·difficulty_norm + b4·log_recall_streak )
    初始系数 a=0, b1=0.5, b2=0.6, b3=−0.3, b4=0.2        # 【工程】初始值，随事件拟合
    difficulty_norm = (item_difficulty − 3)/2 ;  last_recall_ok ∈ {0,1}
P(recall) = 2 ^ ( −Δt_days / half_life_days )
    Δt_days = (now − log_last_review_ts) 的天数（首次复习 → Δt=0，P=1）

# 下次复习时间（解 P(recall)=θ_target）
θ_target = 0.7                                       # 【工程】
Δt* = −half_life_days × log2(θ_target) = 0.515 × half_life_days
next_review_at = log_last_review_ts + Δt* 天
pred_recall_prob = P(recall) 在当前 Δt 处的值
user_forgetting_rate = 1 / half_life_days            # 越大越快忘

# 毕业（方向8 [13]）
mastered = (log_recall_streak ≥ 3) 且 (half_life_days ≥ 30)   # 阈值【工程】
```

#### 4.3.3 冷启动 / 升级 / 降级

| 阶段 | 形态 | 做法 |
|---|---|---|
| **S0** | 规则 | 固定扩展间隔 × 目标保持比例：首次 1 天，之后 ×1.8；按保持期 5%–40% 缩放（方向8 [1][5]，比例【外推】） |
| **S1** | 经典 | 半衰期回归：`half_life = f(复习次数, 历史正误, 项目难度)`，`P(recall)=2^(−Δt/half_life)`（方向8 [20]） |
| **S2** | 经典+层级 | 自适应遗忘曲线参数（per-user）（方向8 [23]） |
| **降级 S2→S1** | 经典 | 回退 HLR |
| **降级 S1→S0** | 规则 | 扩展间隔固定表（`保持期 × 10–20%`），再退 → 固定间隔模板 |
| **缺特征兜底** | — | 无回忆记录 → 群体中位数半衰期；无难度标签 → θ=0（中等） |

**升级触发**：S1：该用户复习事件 ≥50；S2：≥200 item 事件且 Brier 分数 ↓ ≥10%。**【工程】**
**毕业规则**：连续多次成功且长间隔仍成功 → `mastered=true`，转稀疏抽查（方向8 [13]）。
**积压规则**：`log_review_backlog > cap` 时优先保高频/高价值 item，低价值降级而非雪崩（方向8 [26]）；`review_backlog_cap` 默认 20【工程】。

#### 4.3.4 输出形式与消费方

- **输出**：`next_review_at`、`pred_recall_prob`。
- **消费方**：RO-4 Scheduler（复习任务作为普通任务占时段/负荷配额，方向8 [19][22]）；RO-5 RuleEngine（R7 复习到期强制、R8 积压上限）。

**依据**：方向8 [1][5][2][9][10][6][11][19][20][22][16][17][23][26]。

### 4.4 M4 User State Estimator（用户状态估计）

这是整个系统的"仪表盘"，分 4 个子模型，各自独立更新；**M4 的全部输出都是 M1/M2/M7 的输入，且只被 RO-3 的问卷/行为信号喂养**。

#### 4.4.1 M4a Skill / Mastery（技能掌握）

**(1) 依据什么建立**
- 用 BKT 起步：小数据 + 可解释需求下 BKT（四参数概率模型）最合适（方向11 [9][11]）；个体化学习率比个体化先验更有效（方向11 [11]）。
- 不用 DKT 起步：深度知识追踪需要大量交互（方向11 [10][12]），冷启动不适用。
- 自然行为日志可估计个体学习率与迁移（方向11 [4]）。

**(2) 完整参数定义**

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 技能 ID | `skill_id` | str | — | 任务标签 | 任务创建时 | — |

| 练习机会次数 | `item_opportunity_count` | int（次） | ≥0 | 日志 | 每次作答 +1 | `0` |
| 用户学习率 | `user_learn_rate` | float（0–1 转移概率） | 0–1 | M4a 个体（分层贝叶斯） | 每次作答 | `0.15`（BKT 默认学习率） |

**(2b) 参数计算方式**

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `skill_id` | 原始 | 任务标签主键，不做计算 | 【工程】 |
| `item_correct` | 原始 | 本次答对/完成质量（bool），直接来自日志 | 方向11 [9] |
| `item_opportunity_count` | 派生 | 该 skill 的累计作答次数（每次 +1） | 【工程】 |
| `user_learn_rate` | 派生 | 分层贝叶斯估计的个体学习率 `T_j`（见下式） | 方向11 [11] |
| `state_skill_mastery` | 派生（模型输出） | BKT 的后验掌握概率 `P(L_t)`（见下式） | 方向11 [9] |

**主公式（BKT 四参数；方向11 [9]，参数值为【工程】）**：

```text
# 参数：T=学习转移率(0.15)、S=失误率(0.1)、G=猜测率(0.2)、P(L_1)=先验掌握(0.3)
# 每次作答后（先学习转移，再观测更新）
P(L_t^-) = P(L_{t−1}) + (1 − P(L_{t−1})) · T                  # 学习
若 item_correct = true :
    P(L_t) = P(L_t^-)(1−S) / [ P(L_t^-)(1−S) + (1−P(L_t^-))·G ]
若 item_correct = false :
    P(L_t) = P(L_t^-)·S / [ P(L_t^-)·S + (1−P(L_t^-))(1−G) ]
state_skill_mastery = P(L_t)

# 个体学习率（S2 分层贝叶斯）
T_j ~ Beta(α, β)，群体超先验 α=1.5, β=8.5（均值 ≈ 0.15）      # 【工程】
T_j 的后验 = 用该用户该技能的作答序列以 EM / 吉布斯采样更新    # 方向11 [11]
```

#### 4.4.2 M4b Energy / Fatigue（精力 / 疲劳）

**(1) 依据什么建立**
- 主观 VAS 是评估精神疲劳最实用工具（方向1 [3]）；反应时个体内变异 CV 是最敏感可观测指标（方向1 [6]）；打字动力学反映疲劳（方向1 [9]），大型生态数据中打字速度随清醒时长非线性下降（方向5 [24]）。
- 疲劳是部分可观测隐状态，宜用状态空间模型（方向1 [7]）。
- 单次任务损耗效应不可靠，别过度解读单点（方向1 [16]）；疲劳对学习类任务并非全坏（方向1 [24]）。
- 不用更深的时序模型起步：打卡天数通常只有几十，EWMA + 规则更稳。

**(2) 完整参数定义**

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 自评精力 | `self_energy_vas` | float（1–5 档） | 1–5 | 每日打卡 D1 | 每日 1 次 | 近 7 天同时段均值；全无 → 0.5 |
| 自评疲劳 | `self_fatigue_vas` | float（1–5 档） | 1–5 | 每日打卡/任务后 | 每日/每任务 | 由精力反向映射 |
| 作答反应时变异系数 | `log_rt_cv` | float（无量纲 CV） | ≥0 | 作答日志聚合 | 每任务 | 该用户历史中位数 |
| 打字速度 | `log_typing_wpm` | float（词/分钟） | ≥0 | 客户端行为聚合 | 会话级 | 该用户历史中位数 |
| 打字错误率 | `log_typing_error_rate` | float（0–1） | 0–1 | 客户端行为聚合 | 会话级 | `0` |
| 连续高认知任务数 | `log_consecutive_high_cog` | int（个） | ≥0 | 执行日志 | 每任务 | `0` |
| 睡眠时长 | `log_sleep_hours` | float（小时） | 0–24 | 打卡（每周 3 次，RO-3 D4） | 每周约 3 次 | 该用户近 7 天均值 |
| 排程时刻 | `sched_hour` | int（小时） | 0–23 | 排程 | 排程时 | 当前小时 |
| 连续会话时长 | `log_session_minutes` | float（分钟） | ≥0 | 执行日志 | 每次会话 | `0` |

**(2b) 参数计算方式**

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `self_energy_vas` / `self_fatigue_vas` | 原始 | 每日打卡 D1 / 任务后自评（1–5），不做计算 | 方向1 [3][21][22] |
| `log_rt_cv` | 派生 | 会话/窗口内 `sd(RT)/mean(RT)`（窗口 m=20 次作答） | 方向1 [6] |
| `log_typing_wpm` / `log_typing_error_rate` | 原始 | 客户端行为聚合值（词/分、错误率） | 方向1 [9]；方向5 [24] |
| `log_consecutive_high_cog` | 派生 | 自最近一个非高认知任务起的高认知任务计数 | 方向5 [13] |
| `log_sleep_hours` | 原始 | 打卡 D4（每周约 3 次） | 方向7 [14] |
| `sched_hour` | 原始 | 排程上下文 | 【工程】 |
| `log_session_minutes` | 原始 | 连续会话时长（执行日志） | 【工程】 |
| `state_energy` / `state_fatigue` | 派生（模型输出） | S1 自评 EWMA；S2 自评+行为融合（见下式） | 方向1 [3][6][7][9]；方向5 [24] |

**主公式**：

```text
# 1) 归一化
vas_norm(v) = (v − 1) / 4                     # 1–5 → 0–1
# 2) 行为疲劳信号（0=不疲劳, 1=最疲劳）；base 取个人 30 天中位数
b_rt    = clamp( (log_rt_cv − cv_base) / (2·cv_base), 0, 1 )
b_type  = clamp( 1 − log_typing_wpm / wpm_base, 0, 1 )
b_err   = clamp( log_typing_error_rate / err_base, 0, 1 )
b_sleep = clamp( 1 − log_sleep_hours / 7.5, 0, 1 )          # 7.5h 参考【工程】

# 3) S1：自评 EWMA（指数加权移动平均）
E_t = 0.30·vas_norm(self_energy_vas_t) + 0.70·E_{t−1}       # α=0.30【工程】
F_t = 0.30·vas_norm(self_fatigue_vas_t) + 0.70·F_{t−1}

# 4) S2：自评+行为加权融合（权重和为 1）
state_energy  = 0.50·E_t + 0.20·(1−b_rt) + 0.20·(1−b_type) + 0.10·(1−b_sleep)   # 【工程】
state_fatigue = 1 − state_energy
    （可选时段先验 E0(hour)：下午/晚低谷乘性下调，【工程】）

# 5) S2 状态空间（卡尔曼类，方向1 [7] 的隐状态思路）
x_t = x_{t−1} + w_t ,  y_t = x_t + v_t   （x=隐疲劳，y=上式的观测融合值；w,v 为过程/观测噪声）
```

**(3) 冷启动 / 升级 / 降级**

| 阶段 | 形态 | 做法 |
|---|---|---|
| **S0** | 规则 | 自评 VAS 直接映射 + 时段先验（下午/晚低谷） |
| **S1** | 统计 | EWMA（指数加权移动平均）+ 规则；分钟级更新 |
| **S2** | 统计/经典 | 自评+行为信号加权融合；状态空间模型（卡尔曼类）/GAM；触发 n_days ≥ 30（方向1 [7]；方向5 [25]） |
| **降级 S2→S1** | 统计 | 融合模型 → 自评 VAS 单维映射 |
| **降级 S1→S0** | 规则 | 中性默认 0.5，且**不做**任何基于疲劳的调整 |
| **缺特征兜底** | — | 当日未打卡 → 用近 7 天同时段均值；全无 → 0.5 |

- 输出：`state_fatigue`、`state_energy` + 不确定性。
- 消费方：M1/M5；RO-4 Scheduler（疲劳时段安排内隐/复习任务，方向1 [24]）。

**依据**：方向1 [3][6][7][9][16][21][22][24]；方向5 [24]。

#### 4.4.3 M4c Self-efficacy（自我效能）

**(1) 依据什么建立**
- 自我效能是拖延的因也是果，存在恶性/良性循环（方向2 [23]）；低自我效能预测更高拖延（方向2 [5]）；SRL 元分析中自我效能是最强预测构念之一（方向11 [19]）。
- 只做单题自评 + 时变更新，不需要 ML：这是一个主观信念，行为日志只能间接推断。

**(2) 完整参数定义**

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 自我效能单题自评 | `self_efficacy_1item` | float（1–5 档） | 1–5 | 注册问卷 + 每周 1 题（"我有信心完成今天的任务"） | 注册时 + 每周 | 中性 `0.5` |
| 近期成功强度 | `log_recent_success` | float（0–1 加权） | 0–1 | 任务结果日志 | 每次成败后 | `0.5` |
| 近期失败强度 | `log_recent_failure` | float（0–1 加权） | 0–1 | 任务结果日志 | 每次成败后 | `0` |
| 努力投入比 | `log_effort_ratio` | float（实际/计划） | >0 | 日志 | 每任务 | `1.0` |

**(2b) 参数计算方式**

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `self_efficacy_1item` | 原始 | 注册问卷 / 每周 1 题自评（1–5），不做计算 | 方向11 [19] |
| `log_recent_success` | 派生 | 近期任务成功率分的指数衰减加权（见下式） | 方向2 [23] |
| `log_recent_failure` | 派生 | 近期任务失败分的指数衰减加权（见下式） | 方向2 [5][23] |
| `log_effort_ratio` | 派生 | `actual_min / alloc_min`（alloc=分配的 q80 时长） | 【工程】 |
| `state_self_efficacy` | 派生（模型输出） | 事件 EWMA + 每周自评回锚（见下式） | 方向2 [5][23]；方向11 [19] |

**主公式**：

```text
# 1) 事件成功分 s_i：完成=1；部分完成=log_partial_pct（0–1）；没做=0
# 2) 近期成功/失败（指数衰减，越近权重越大）
w_i = γ^{age_i} ,  γ=0.80【工程】 ,  age=距今天数
log_recent_success = Σ_{i=1..k} w_i·s_i / Σ_{i=1..k} w_i        # k=10【工程】
log_recent_failure = Σ_{i=1..k} w_i·(1−s_i) / Σ_{i=1..k} w_i

# 3) 时变更新（每次任务成败后；失败权重更大，体现恶性循环）
SE_0 = (self_efficacy_1item − 1)/4
SE_t = SE_{t−1} + 0.15·s_t·(1 − SE_{t−1}) − 0.25·(1−s_t)·SE_{t−1}     # η_s=0.15, η_f=0.25【工程】
clamp(SE_t, 0, 1)

# 4) 每周自评回锚（防止只由行为漂移）
SE ← 0.70·SE_behavior + 0.30·vas_norm(self_efficacy_1item)            # λ=0.30【工程】
state_self_efficacy = SE
```

**(3) 冷启动 / 升级 / 降级**
- **S0**：单题自评直接映射。
- **S1**：每次成功/失败后 EWMA；成功提升、失败下降（恶性/良性循环）。
- **S2**：同 S1（**不升级 ML**）。
- **降级**：时变更新 → 静态使用注册值；未填 → 中性 0.5，且下游特征权重减半。

**(4) 输出形式与消费方**
- 输出：`state_self_efficacy`（0–1 点估计）。
- 消费方：M2；RO-3 引导话术（打破恶性循环，方向2 [23]）。

**依据**：方向2 [5][23]；方向11 [19]。

#### 4.4.4 M4d Stress（压力，慢变量）

**(1) 依据什么建立**
- 自评压力有前瞻预测价值但横断面相关弱，应作慢变量（方向6 [18][19][20]）；压力方向不可预设单向，必须分解（方向6 小结 1、2）；压力升高→拖延风险（方向6 [17]）。
- 压力来源比总分更有预测力（方向6 [19]）。
- 不用 ML：慢变量、双周频次，样本不足以训练；且必须保持可解释以便审计。

**(2) 完整参数定义**

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 感知压力双题 | `self_stress_2item`（每题一个字段：`self_stress_1`,`self_stress_2`） | int（0–4）各题 | 0–4 | 双周问卷（PSS 精简，RO-3 Q9） | 每两周 | 沿用上期值并标 `stale=true` |
| 压力来源画像 | `self_stress_source` | enum[] 多选 | `学业应对失败/时间不够/人际/经济/健康/对未来不确定` | 双周问卷（RO-3 Q10） | 每两周 | 空数组 |
| 深夜活动标记 | `log_night_activity` | bool | true/false | 日志（23:00 后活动） | 每日 | `false` |
| 连续未执行天数 | `log_skip_days` | int（天） | ≥0 | 日志 | 每日 | `0` |

**(2b) 参数计算方式**

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `self_stress_1` / `self_stress_2` | 原始 | 双周问卷两题（各 0–4），不做计算 | 方向6 [18][19] |
| `self_stress_source` | 原始 | 双周问卷多选直接落库 | 方向6 [19] |
| `log_night_activity` | 原始 | 当日 23:00 后是否有活动（bool） | 方向6 [23] |
| `log_skip_days` | 派生 | 结尾连续"当日 `completion_rate_day < 0.5`"的天数 | 【工程】阈值 |

**主公式**：

```text
# 1) 问卷标准化
stress_raw = self_stress_1 + self_stress_2                 # 0–8
z_stress   = clamp((stress_raw − 4) / 2, −2, 2)            # μ=4, σ=2【工程】

# 2) 行为代偿指数（0–1）
b_night = 1 若过去 7 天 log_night_activity 次数 ≥ 3，否则 0        # 阈值【工程】
b_skip  = clamp(log_skip_days / 5, 0, 1)                          # 5 天【工程】
behavior_index = 0.5·b_night + 0.5·b_skip                         # 【工程】

# 3) 融合（行为只作辅助，问卷为主；方向6：来源比总分更有预测力）
state_perceived_stress = 0.70·z_stress + 0.30·(2·behavior_index − 1)   # λ=0.70【工程】
    （慢变量：不参与单点硬决策；缺失 → 沿用上期并标 stale=true）
```

**(3) 冷启动 / 升级 / 降级**
- **S0**：问卷分数标准化。
- **S1**：双周复测标准化。
- **S2**：同 S1（**慢变量不上 ML**）。
- **降级**：复测缺失 → 沿用上期值并标记 `stale=true`（慢变量，权重低）；未填 → **不参与任何调整**（压力方向不可预设，方向6 小结）。

**(4) 输出形式与消费方**
- 输出：`state_perceived_stress` + `stress_source_profile`（慢变量点估计）。
- 消费方：M5；RO-4/RO-5（压力调节**不做全局单调规则**）。

**依据**：方向6 [1][2][17][18][19][20]；方向6 小结 1、2。

### 4.5 M5 Replan Trigger（重规划触发器）

**要解决**：计划跑偏了，要不要重排？局部修还是全量大改？（完整策略见 RO-4 §4.10。）

#### 4.5.1 依据什么建立

- 动态调度需权衡"性能"与"稳定性"，事件驱动/周期驱动各有适用（方向9 [24]）；局部修复优于全面重排（方向9 [25][28]）；滚动时域 + 只执行一步 + 约束可避免震荡（方向9 [26]）。
- 冷启动用确定性规则即可（阈值可解释、可审计）；学习版（Q-learning）需 ≥30 次重规划事件后再评估（方向9 [14][18]），【工程】门槛。
- 为什么不用纯 ML：重规划事件稀疏，且决策影响大，早期必须可解释。

#### 4.5.2 完整参数定义

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 近 3 天完成率 | `log_completion_rate_3d` | float（0–1） | 0–1 | 日志聚合 | 每日 | 近 7 天完成率；全无 → 0.7 |
| 耗时偏差滚动均值 | `log_duration_deviation` | float（无量纲） | 典型 −1~+3 | `(实际−预测)/预测` 滚动 | 每任务/每日 | `0` |
| 近 7 天重规划次数 | `log_replan_count_7d` | int（次） | ≥0 | 系统日志 | 每次重规划 | `0` |
| 计划稳定度 | `log_schedule_stability` | float（0–1，`1−改动比例`） | 0–1 | 系统 | 每次重规划 | `1.0` |
| 连续未达标天数 | `log_consecutive_fail_days` | int（天） | ≥0 | 日志 | 每日 | `0` |
| 疲劳状态 | `state_fatigue` | float（0–1） | 0–1 | M4b | 分钟级 | `0` |
| 感知压力 | `state_perceived_stress` | float（标准化） | 标准化值 | M4d | 双周 | 不参与（缺失即跳过） |
| 复习积压数 | `log_review_backlog` | int（条） | ≥0 | 复习队列 | 每日 | `0` |
| 距截止天数 | `sched_days_to_deadline` | int（天） | ≥0 | 排程 | 每日 | 无 → 置大值 |
| 完成概率预测 | `pred_completion_prob` | float（0–1） | 0–1 | M2 | 每任务 | `0.7` |
| 放弃模式 | `log_abandon_pattern` | enum | `onset_delay/mid_quit/whole_day_skip` | 日志 | 每任务/每日 | `none` |

#### 4.5.2b 参数计算方式

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `log_completion_rate_3d` | 派生 | `completed_3d / planned_3d`；`planned_3d=0` → 近 7 天值 | 方向9 [24] |
| `log_duration_deviation` | 派生 | `mean_i( (actual_i − pred_i)/pred_i )`，i=最近 k=10 个已完成任务 | 方向10 [24]；k【工程】 |
| `log_replan_count_7d` | 派生 | 过去 7 天重规划事件计数 | 方向9 [24] |
| `log_schedule_stability` | 派生 | `1 − changed_tasks / total_tasks`（上次重规划） | 方向9 [24]；公式【工程】 |
| `log_consecutive_fail_days` | 派生 | 结尾连续"当日 `completion_rate_day < 0.6`"的天数 | 方向9 [24]；阈值【工程】 |
| `state_fatigue` | 派生（跨模型） | 见 §4.4.2 | 方向1 [3] |
| `state_perceived_stress` | 派生（跨模型） | 见 §4.4.4；缺失即跳过 | 方向6 [18] |
| `log_review_backlog` | 派生（跨模型） | 见 §4.3.2b | 方向8 [26] |
| `sched_days_to_deadline` | 派生 | `(deadline − today).days` | 【工程】 |
| `pred_completion_prob` | 派生（跨模型） | 见 §4.2.2b | 方向11 [19] |
| `log_abandon_pattern` | 派生 | 规则分类：启动延迟 / 中途放弃 / 整日跳过 | 【工程】 |
| `replan_decision` | 派生（模型输出） | 确定性树，见下式 | 方向9 [24][25][28] |

**主公式（确定性决策树，阈值【工程】）**：

```text
C3 = log_completion_rate_3d ;  D = log_duration_deviation
若 C3 ≥ 0.70 且 |D| ≤ 0.30                         → none
否则若 (连续 2 天 C3 < 0.60) 或 (D > 0.50)          → local_repair
否则若 (连续 5 天 C3 < 0.40) 或 deadline_infeasible  → full_replan
若距上次 full_replan < 48h                            → 强制降级为 local_repair
    deadline_infeasible = (剩余任务 q80 总时长) > (距 deadline 可用时长)
```

#### 4.5.3 冷启动 / 升级 / 降级

**S0 冷启动规则（【工程】默认值）**：
```
none           : 完成率 ≥ 70% 且 |deviation| ≤ 30%
local_repair   : 完成率 < 60% 连续 2 天 或 deviation > 50%（只调受影响任务段）
full_replan    : 完成率 < 40% 连续 5 天 或 deadline 在现有节奏下不可达
cooldown       : 同一用户 48h 内已有 full_replan → 强制降级为 local_repair
```

| 阶段 | 形态 | 做法 |
|---|---|---|
| **S0** | 规则 | 上述确定性规则 |
| **S1** | 统计/经典 | 多分类 Logistic / 规则+阈值校准 |
| **S2** | ML | GBDT；≥30 次重规划事件后再考虑 Q-learning（方向9 [14][18]） |
| **降级 S2→S1** | 规则 | 学习版 → 纯规则触发（§4.5.3 阈值） |
| **缺特征兜底** | — | 特征不全 → 只用完成率单一信号 |

**上线门槛**：规则版零门槛（P0 即上）；学习版需重规划事件 ≥30 且人工抽检通过率 ≥90%。**【工程】**

#### 4.5.4 输出形式与消费方

- **输出**：`replan_decision ∈ {none, local_repair, full_replan}` + 置信度 + `reason_code` + 预期调整幅度。
- **消费方**：RO-4 §4.10；RO-5 RuleEngine（R11 冷却、R12 幅度上限）。

**依据**：方向9 [24][25][26][27][28][30]；方向10 [24]。

### 4.6 M6 LLM Router（大模型门控路由）

**要解决**：这一步到底要不要叫大模型？叫小的还是大的？（门控与验证的完整设计见 RO-6。）

#### 4.6.1 依据什么建立

- LLM 长程任务成功率低（方向10 [29][30]），应减少对模型能力的依赖、用结构兜底；外部验证器 > 内部自省（方向10 [11][19]）；采样一致性分歧可作不确定性信号（方向10 [27]）；语法约束解码可 100% 保证格式合法（方向10 [25]）；验证要步骤级（方向10 [16]）。
- 冷启动用三层规则（L0/L1/L2 + abstain）即可，零成本、可审计；学习型路由器需 ≥100 次路由记录且离线验证"省成本不降质"（方向10 [4]），【工程】门槛。

#### 4.6.2 完整参数定义

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 目标模糊度 | `goal_ambiguity_score` | float（0–1） | 0–1 | 规则/小模型评分 | 每次请求 | `0.5` |
| 规则覆盖标记 | `rule_coverage_flag` | bool | true/false | RuleEngine | 每次请求 | `false` |
| 校验通过标记 | `validator_pass` | bool | true/false | RuleEngine | 每次请求 | `false` |
| 计划一致性分歧度 | `plan_consistency_divergence` | float（0–1） | 0–1 | k=2–3 次采样的一致性 | 每次请求 | 无 → 视为低（默认 L1） |
| 相似成功方案数 | `log_similar_solved` | int（条） | ≥0 | 历史检索 | 每次请求 | `0` |
| 剩余预算 | `budget_remaining` | float（元/额度） | ≥0 | 系统 | 每次调用 | 无 → 0（强制 L0） |
| 用户档位 | `user_tier` | enum | `free/paid` | 系统 | 注册/变更 | `free` |

#### 4.6.2b 参数计算方式

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `goal_ambiguity_score` | 派生 | 三因子加权（见下式） | 方向10 [1][2]；权重【工程】 |
| `rule_coverage_flag` | 原始 | RuleEngine 直接给出 bool | 方向10 [1][2][3] |
| `validator_pass` | 原始 | RuleEngine 直接给出 bool | 方向10 [11][20] |
| `plan_consistency_divergence` | 派生 | `1 − k 次采样的平均两两余弦相似度`（见下式） | 方向10 [27] |
| `log_similar_solved` | 派生 | 历史成功计划中与当前目标相似度 ≥ 0.85 的条数 | 方向10 [13][14]；阈值【工程】 |
| `budget_remaining` | 原始 | 系统预算余额 | 【工程】 |
| `user_tier` | 原始 | 用户档位 | 【工程】 |
| `route` | 派生（模型输出） | 规则树（见下式） | 方向10 [1][2][5][6] |

**主公式**：

```text
# 1) 目标模糊度（0–1）
goal_ambiguity_score = clamp(0.40·m1 + 0.30·m2 + 0.30·s_llm, 0, 1)
    m1 = 1 若缺少"可验证完成判据"，否则 0
    m2 = 1 若缺少明确 deadline，否则 0
    s_llm = 小模型对目标模糊度的评分（0–1）
    权重 0.40/0.30/0.30【工程】

# 2) 计划一致性分歧度（k=3 次采样）
plan_consistency_divergence = 1 − ( 2 / (k(k−1)) ) · Σ_{i<j} cos(emb_i, emb_j)
    emb = 计划文本的嵌入向量；cos ∈ [−1,1] 截断到 [0,1] 后计算     【工程】

# 3) 相似成功方案
log_similar_solved = |{ h ∈ 历史计划 : cos(emb_h, emb_goal) ≥ 0.85 ∧ outcome_h = success }|  # 【工程】

# 4) 路由规则（阈值【工程】；validator_pass=0 时升级一级）
若 rule_coverage_flag = true                                   → deterministic
否则若 budget_remaining ≤ 0                                     → abstain
否则若 goal_ambiguity_score ≥ 0.60 或 divergence ≥ 0.50        → frontier_llm
否则若 goal_ambiguity_score ≥ 0.30                              → small_llm
否则                                                            → deterministic
若 validator_pass = false 且 route ≠ abstain → route 升级一级（small_llm→frontier_llm；frontier_llm→abstain）
```

#### 4.6.3 冷启动 / 升级 / 降级

| 阶段 | 形态 | 做法 |
|---|---|---|
| **S0** | 规则 | 纯规则：规则覆盖→`deterministic`；目标模糊→`small_llm`；验证失败→`frontier_llm`；高不确定→`abstain` |
| **S1** | 统计 | 阈值校准（在历史路由数据上学成本-收益） |
| **S2** | ML | 学习型路由器；触发 ≥100 次路由记录且离线验证"省成本不降质"（方向10 [4]） |
| **降级 S2→S1** | 规则 | 学习版 → 规则门控（L0→L1→L2 固定规则） |
| **缺特征兜底** | — | 无分歧度信号 → 默认 L1；预算耗尽 → 强制 L0 + abstain |

**输出**：`route ∈ {deterministic, small_llm, frontier_llm, abstain}` + `max_tokens` + `reason_code`。
**约束**：大模型输出必须过 **GCD 语法约束** + **外部 RuleEngine 语义校验**（方向10 [25]；方向10 [11][19]）。

#### 4.6.4 输出形式与消费方

- **消费方**：RO-6 Harness；RO-4 重规划流（M6 裁决 L0/L1/L2）。

**依据**：方向10 [1][2][4][5][6][11][16][19][20][25][27][29][30][31]。

### 4.7 M7 Task Difficulty Estimator（任务难度估计）

**要解决**：这个任务到底多难？（用于难度适配与前置依赖。）

#### 4.7.1 依据什么建立

- 学习任务前期应设学习目标而非绩效目标（方向3 [6]）；一次 3–4 块以内（方向3 [31]）；难度对耗时影响存在个体交互（方向4 结论 4）；专家反转：同一任务负荷因人而异（方向5 小结 5）。
- 冷启动用 LLM 难度标签 + 群体先验，因为新任务没有作答数据；IRT 归因需要 item 作答 ≥200（方向4 结论 4 的交互 + IRT 思路），【工程】门槛。
- 为什么不用深度模型：item 交互量在早期远不够；IRT/ELO 是可解释的经典模型。

#### 4.7.2 完整参数定义

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| LLM 难度标签 | `task_difficulty_llm` | float（1–5 档） | 1–5 | LLM | 任务创建时 | `3` |
| 同技能历史成功率 | `item_historical_success` | float（0–1） | 0–1 | 日志 | 每次作答 | 群体基准率 |
| 技能掌握概率 | `state_skill_mastery` | float（0–1） | 0–1 | M4a | 每次作答 | `0.3` |
| 前置技能掌握度 | `item_prereq_mastery` | float（0–1） | 0–1 | M4a（前置 skill） | 每次作答 | `0.3` |
| 反应时标准化 | `log_response_time_z` | float（z 分数） | 典型 −3~+3 | 日志标准化 | 每次作答 | `0` |

#### 4.7.2b 参数计算方式

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `task_difficulty_llm` | 原始 | LLM 难度标签 1–5，不做计算 | 方向3 [6] |
| `item_historical_success` | 派生 | 同 skill 窗口内 `correct / attempts`（窗口 30） | 方向4 结论 4；窗口【工程】 |
| `state_skill_mastery` | 派生（跨模型） | 见 §4.4.1 | 方向11 [9] |
| `item_prereq_mastery` | 派生 | `min_{p∈prereq}(state_skill_mastery_p)`（取最弱前置） | 方向3 [6]；聚合方式【工程】 |
| `log_response_time_z` | 派生 | `(RT − μ_item) / σ_item`（item 与个人层面的均值/标准差） | 方向4 结论 4 |
| 难度 `θ` / `P(success)` | 派生（模型输出） | IRT/Elo 式（见下式） | 方向4 结论 4；方向11 [22] |

**主公式**：

```text
# 1) 难度参数 b（由 LLM 标签映射；S0/S1）
b_item = 0.5 × (task_difficulty_llm − 3)          # 标签 1–5 → b ∈ [−1,1]【工程】

# 2) 答对概率（1PL / Rasch 形式；能力 θ、难度 b）
P(success) = 1 / (1 + e^( −(θ_ability − b_item) ))

# 3) 能力 θ 在线更新（Elo 式，S2）
θ ← θ + K·(outcome − P(success)) ,  K=0.10【工程】 ,  outcome ∈ {0,1}
    θ 初值 0；同一用户跨 skill 共享时改按 skill 分别维护

# 4) 输出
θ + 置信区间（由答题次数近似）；item_historical_success 作独立行为校核
```

#### 4.7.3 冷启动 / 升级 / 降级

| 阶段 | 形态 | 做法 |
|---|---|---|
| **S0** | 规则 | LLM 难度标签（1–5）+ 群体先验映射 |
| **S1** | 统计 | 按历史通过率校准 |
| **S2** | 经典 | IRT 式 θ 估计 / Elo / BKT 联动；触发 item 作答 ≥200 |
| **降级 S2→S1** | 统计 | 学习版 → LLM 先验标签 |
| **降级 S1→S0** | 规则 | 按 `task_type` 的固定难度映射表 |
| **缺特征兜底** | — | 无交互数据 → 用 LLM 标签直出 |

**输出**：难度 θ（IRT/ELO 式）+ `P(success)` + 置信区间。

#### 4.7.4 输出形式与消费方

- **消费方**：RO-4 Scheduler（难度适配 `fit` 因子）；M1（难度对耗时交互）；RO-5。

**依据**：方向3 [6][31]；方向4 结论 4；方向5 小结 5；方向11 [22]。

### 4.8 M8 Prompt / Interruption Policy（打扰策略）

**要解决**：现在该不该打扰用户？（问卷/提示的频次与时机裁决，详见 RO-3。）

#### 4.8.1 依据什么建立

- 降低反馈频率促进长期保持（方向9 [9][10]）；反馈平均有效但 >1/3 有害（方向9 [6]）；JITAI 强调"状态（availability/receptivity）"（方向9 [12]）；混合主动式按期望效用决定是否打扰（方向9 [30]）。
- 冷启动用规则（频率上限 + 决策点）即可；上下文 bandit 需 ≥200 决策点（方向9 [13]），【工程】门槛。

#### 4.8.2 完整参数定义

| 全称中文名 | 字段名 | 类型/量纲 | 取值范围 | 采集来源 | 更新频率 | 缺失时的兜底值 |
|---|---|---|---|---|---|---|
| 24 小时提示次数 | `log_prompt_count_24h` | int（次） | ≥0 | 日志 | 每次提示 | `0` |
| 提示忽略率 | `log_prompt_ignore_rate` | float（0–1） | 0–1 | 日志 | 滚动 14 天 | `0` |
| 可接受提醒状态 | `state_receptivity` | float（0–1） | 0–1 | 估计（JITAI availability/receptivity） | 每次决策点 | `0.5` |
| 是否专注块内 | `log_current_focus_block` | bool | true/false | 系统 | 实时 | `false` |
| 执行势头 | `log_momentum` | float（连续执行强度） | ≥0 | 日志（`log_streak` 等） | 每日 | `0` |
| 打扰成本 | `pred_interruption_cost` | float（估计值） | ≥0 | 估计/规则 | 每次决策点 | 默认中值 |

#### 4.8.2b 参数计算方式

| 参数 | 类别 | 计算方式 | 来源 |
|---|---|---|---|
| `log_prompt_count_24h` | 派生 | 过去 24 小时已发送提示/追问计数 | 方向9 [9][10] |
| `log_prompt_ignore_rate` | 派生 | `ignored / sent`（滚动 14 天） | 方向9 [6][30] |
| `state_receptivity` | 派生 | 四因子加权（见下式） | 方向9 [12]；权重【工程】 |
| `log_current_focus_block` | 原始 | 系统直接给出 bool | 【工程】 |
| `log_momentum` | 派生 | `0.6·min(log_streak/7,1) + 0.4·log_completion_rate_7d` | 方向3 [18]；权重【工程】 |
| `pred_interruption_cost` | 派生 | 三因子加权（见下式） | 方向9 [30]；权重【工程】 |
| `send / defer` | 派生（模型输出） | 效用比较（见下式） | 方向9 [30] |

**主公式**：

```text
# 1) 执行势头（0–1）
log_momentum = 0.60·min(log_streak/7, 1) + 0.40·log_completion_rate_7d      # 【工程】

# 2) 可接受提醒状态（0–1）
state_receptivity = clamp(
      0.35·(1 − focus) + 0.25·(1 − log_prompt_ignore_rate)
    + 0.20·log_momentum + 0.20·(1 − state_fatigue), 0, 1)                    # 权重【工程】

# 3) 打扰成本（0–1）
pred_interruption_cost = 0.50·focus + 0.30·log_prompt_ignore_rate + 0.20·(1 − state_receptivity)  # 【工程】

# 4) 期望效用决策
expected_gain = Δp × V
    Δp = pred_completion_prob(有提示) − pred_completion_prob(无提示)（用同状态历史估计）
    V  = 任务价值（0–1，来自 RO-4 value 因子）
send 当且仅当：
    expected_gain − pred_interruption_cost > 0
    且 log_prompt_count_24h < 3
    且 log_current_focus_block = false
否则 → defer
```

#### 4.8.3 冷启动 / 升级 / 降级

| 阶段 | 形态 | 做法 |
|---|---|---|
| **S0** | 规则 | 每天主动提示 ≤3 次；专注块内不发；非预期时点（【工程】） |
| **S1** | 统计 | 按历史响应率调频 |
| **S2** | 经典 | 效用模型 / 上下文 bandit（≥200 决策点）；用微随机试验估因果（方向9 [13]） |

### 4.10 现在明确不建的模型（避免过度工程）

- **不做神经/生理模型**：EEG、fMRI、HRV 特征不进入产品闭环（方向1 [18]、方向3 [32][33]、方向5 [25] 均依赖实验室设备，仅作理论参考）。

- **不做自动全量重规划**：默认局部修复（方向9 [25][28]）。

#### 4.11.2 ML 数据量不够时的三条降级路径

1. **从未吃饱（冷启动）**：根本没训练过 ML → 直接用 S0/S1 的规则/统计形态，ML 那一档**不存在**，不是"降级"而是"暂不启用"。
2. **曾经吃饱、后来掉量**（用户活跃度下降，滚动窗口跌破维持阈值，如 M1 全量 <150 条有效样本）：冻结 ML 模型参数不再更新，预测逐步向 S1 统计值**收缩加权**（如 `0.5×ML + 0.5×统计`），数据量跌破维持阈值一半 → 完全退回 S1。
3. **训练后效果不达标**（离线验证 MAE/AUC 未过 §4.0.4 阈值）：ML 版本**不上线**，线上永远是已验证的旧档；保留实验记录，等数据量或特征改善后再评估。

**维持阈值**（【工程】）：S2 模型要求滚动 90 天内有效样本 ≥ 升级阈值的 50%，否则触发路径 2。所有降级/收缩事件写审计日志（`model_version`、`reason_code`、`degraded=true`）。

1. 任何模型上线前必须**离线回测 + shadow 模式**（线上跑但不影响决策）至少 14 天（方向10 [4]；14 天为【工程】）。
