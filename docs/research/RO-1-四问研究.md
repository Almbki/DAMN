## 1. 目标

把 11 个方向的文献调研（精力与疲劳、拖延、任务拆解、任务耗时、认知负荷、压力与目标完成、时间段与节律、记忆与学习、反馈调节、LLM 规划与 Harness、个体差异），压缩成一张**"研究发现 → 系统变量 → 工程实现 → 证据ID"**的映射表，并回答四个决定系统架构的工程问题：

- **Q1** 哪些科学规律应该固化成**规则**（硬约束）？
- **Q2** 哪些应该进入**用户状态模型**（User State）？
- **Q3** 哪些值得建立**统计模型 / 机器学习模型**？
- **Q4** 哪些交给 **LLM**、什么情况**不该调用**？

产出的结论不直接写成代码，而是作为 RO-2~RO-6 的输入。

## 2. 核心问题（含回答）

### Q1：哪些结论应该固化为规则？

**回答口径**：规则 = "不管模型/LLM 怎么想，系统都这么干"的硬性约束。只有**文献支持度高且变量可观测**的结论才配当规则；证据不足者只能先"观测"（影子运行）。本 RO 只列**候选规则**；落地实现见 RO-5（其中 15 条为 P0 上线规则）。

| # | 候选规则（大白话） | 触发/条件 → 动作 | 依据 | 强度 |
|---|---|---|---|---|
| R1 | LLM 输出一律不是最终结果，必须过规则校验 | 任何 LLM 产出的计划/拆解 → 不过则结构化批评回灌 | 方向10 [11][16][17][19][20] | 强 |
| R2 | 能确定性求解就不调 LLM | 目标可形式化 → 拓扑排序+规则+调度器 | 方向10 [1][2][3][5][6][12] | 强 |
| R3 | 每个任务必须有可验证的完成判据 | 任务生成时 → 缺判据则拒绝入库 | 方向3 [1][2] | 强 |
| R4 | 只给远距离大目标是非法的 | 任务树只有根/远端目标 → 自动展开近端子目标 | 方向3 [4][5] | 强 |
| R5 | 单次任务数上限：单次可完成 + 约 3~4 组块 | 列表渲染/派发 → 超过则分组或继续拆 | 方向3 [4][5][25][31] | 强 |
| R6 | 需要先学知识的任务改用"学习目标"措辞 | `task_type=学习` 或先验低 → "掌握 X"而非"产出 X" | 方向3 [2][6] | 强 |
| R7 | 高厌恶/高模糊任务强制拆小 + if-then 线索 | 厌恶评分高或描述含糊 → 拆到单步 + 绑定触发 | 方向3 [34][9][10] | 中强 |
| R8 | 子目标完成即反馈；失败不得等同总目标失败 | 子任务状态变化 → 即时反馈 + 动机修复 | 方向3 [18][33][21] | 中强 |
| R9 | 高认知任务之间必须插缓冲，不得连续堆叠 | 相邻任务均为高负荷 → 微休息或降级 | 方向5 [5][12][13][15][16][17] | 强 |
| R10 | 每日负荷上限必须个体化，禁止写死 | 生成日计划 → 用个人历史红线约束 | 方向5 [8][18] | 中强 |
| R11 | 练习型任务要交错 + 分散，不集中同日 | 同类练习排程 → 交错到多天 | 方向5 [20][21][22][23]；方向8 [1][11] | 强 |
| R12 | 复习任务默认"先测后看" | 复习任务生成 → 先出检索题再给材料 | 方向8 [2][6][10][11] | 强 |
| R13 | 复习间隔有最小/最大约束，按保持期取"时间山脊" | 复习调度 → 硬约束间隔区间 | 方向8 [1][5][22] | 强 |
| R14 | 反馈降频、指向任务/策略，不指向人身 | 反馈生成/推送 → 频率随熟练度下降 + 模板约束 | 方向9 [6][7][8][9][10] | 中强 |
| R15 | 连续失败 N 次触发降级/换策略 | 连续失败计数达阈值 → 降难度或目标脱离再投入 | 方向9 [4] | 中 |
| R16 | 估时不得用 deadline/可用时长当规模代理 | 构造估时特征 → 白名单排除时限类字段 | 方向4 [5] | 中强 |
| R17 | 估时默认输出保守区间（宁略高勿低估） | 输出估时 → 分位数上界排期、中位数展示 | 方向4 [39][8] | 中强（[39] 为预印本） |
| R18 | 流体认知任务排峰值时段 | 生成日程 → 匹配 peak window | 方向7 [2][13][18][22] | 强 |
| R19 | deadline 用"多段紧时限 + 非预期提醒 + 随机检查点" | 截止期规划 → 避免单一时限与 slippery deadline | 方向2 [14][16][17] | 中 |

> **反例提醒**：不要把"高认知任务不能连续"写成"完全不能连续"——文献支持的是"连续高负荷会累积损伤，需要缓冲/降级"（方向5 [13][8]）。规则要写成可执行的弱版本，而非绝对禁令。
> **落地下沉**：RO-5 从中筛选 15 条为 P0 上线规则（见 RO-5 §4.2）；中以下强度的规则建议先"影子运行"（只记录不拦截）。

### Q2：哪些进 User State？

**回答口径**：User State = 系统对"这个人现在是什么状态、长期是什么特点"的估计，随每次任务执行更新，供所有模块读取。**LLM 只能建议更新理由，不能直接改状态**【工程，与项目架构一致】。

| User State 字段 | 通俗含义 + 例子 | 更新方式 | 依据方向 |
|---|---|---|---|
| `user_skill` | 对某技能多熟（"高数第一章他掌握 70%"） | 每次做题/任务结果 → BKT 更新 | 方向11 [9][11][1][2] |
| `learning_rate` | 学新东西快不快 | 学习曲线分解 / 任务序列 | 方向11 [3][4] |
| `duration_factor`（用户耗时倍率） | 做同类任务比"标准时间"慢/快多少 | `实际耗时 / 理论耗时` 中位数滚动更新 | 方向4 [20][30]；方向11 [1][2] |
| `completion_rate` | 派给他的任务有多少真完成 | 完成/放弃事件累计 | 方向11 [14][15][19] |
| `self_efficacy`（自我效能） | 觉得自己能不能做成（自评 1 题） | 任务成败后自评更新 | 方向11 [16]；方向2 [5][23] |
| `fatigue`（疲劳） | 现在有多累 | 单题自评 + 行为代理（反应时变异、输入动力学） | 方向1 [3][6][9][21][22]；方向5 [18] |
| `workload_redline`（负荷红线） | 一天能扛多少高认知任务 | 负荷-绩效历史估计 | 方向5 [8][18] |
| `stress_response`（压力反应） | 当前压力反应与"威胁/挑战"评价 | 自评（慢变量）+ 行为趋势 | 方向6 [5][18][21] |
| `threat_vs_challenge` | 把当前任务看成威胁还是挑战 | 轻量自评 / 历史模式 | 方向6 [5][10] |
| `chronotype` / `peak_window` | 几点最清醒 | 问卷 + 作息日志 + 行为表现时段推断 | 方向7 [3][5][12][23] |
| `social_jetlag`（社会时差） | 作息与工作日错位多少 | 睡眠中点对比 | 方向7 [5] |
| `bedtime_procrastination`（就寝拖延） | 是否习惯性熬夜 | 就寝时间日志 | 方向7 [15][16] |
| `procrastination_tendency`（拖延倾向） | 习惯性拖不拖 | 历史"意图-行动差距" | 方向2 [12][16][18] |
| `discount_rate`（双曲线贴现率） | 多看重"马上爽" | logs 拟合 | 方向2 [12] |
| `task_aversiveness`（任务厌恶） | 这类任务让他多难受 | 任务属性 + 自评 + 推迟行为 | 方向3 [34]；方向2 [1][20] |
| `goal_commitment`（目标承诺） | 有多认这个目标 | 是否编辑/跳过/接受拆解 | 方向3 [3] |
| `goal_proximity`（目标近端度） | 当前目标离完成还有多近 | 进度计算 | 方向3 [18][20] |
| `implementation_intention_use` | 是否采纳 if-then 线索 | 线索采纳/命中 | 方向3 [9][10] |
| `subgoal_completion_rate` | 子目标完成比例 | 子任务事件 | 方向3 [4][15] |
| `affect_state`（情绪状态） | 当前情绪（被估时误差影响） | 任务前后短自评 | 方向4 [39] |
| `speed_accuracy_preference` | 偏快还是偏准（稳定特质） | 耗时-正确率联合分布 | 方向4 [20] |
| `retention_probability`（保持概率） | 某知识点"快忘了没" | 半衰期回归/点过程 | 方向8 [20][22][23] |
| `exam_readiness` | 面向考试的掌握度 | 复习+测验结果聚合 | 方向8 [31] |
| `bandit_state` / `ability_latent` | 难度自适应用的隐藏能力估计 | bandit/在线学习 | 方向9 [31] |

> **采集原则**（多方向共识）：优先**行为日志**（零打扰、客观），自评只做少量单题补充；人格/心理量表谨慎采集（方向11 [17][18]）。分工与问卷见 RO-3。

### Q3：哪些应该建统计模型或 ML 模型？

**回答口径**：模型 = "从历史数据里学规律来预测"。原则是**先简单可解释，数据够了再升级**（简单模型能审计、能写进规则）。

| 模型 | 预测什么 | 冷启动（数据少时） | 升级路径（数据多了） | 依据 |
|---|---|---|---|---|
| Duration Predictor（耗时预测） | `actual_duration` | 理论时间（KLM）× 用户耗时倍率（历史中位数） | GBDT/XGBoost + 分位数输出 | 方向4 [10][29][30][32][33][36] |
| 用户耗时倍率 | `duration_factor` | 按任务类型分组的比值中位数 | 含 skill/疲劳/时段的回归 | 方向4 [20][21]；方向11 [1][2] |
| 学习曲线 | 熟练度随练习变化 | 单幂律 | 分段幂律 + 变点检测 | 方向4 [15][16]；方向11 [3][4] |
| 知识追踪 | 技能掌握概率 | BKT（四参数，可解释） | 深度知识追踪（数据足够） | 方向11 [9][11][10][12] |
| 复习调度 | 何时该复习 | 固定间隔表（最小/最大） | 半衰期回归 / 点过程 / 队列模型 | 方向8 [20][22][23][26] |
| 遗忘建模 | 保持概率随时间 | 单条遗忘曲线 | 层级模型（个体差异） | 方向8 [12][13][17] |
| 疲劳状态 | 隐藏疲劳水平 | 自评 + 反应时变异 | 状态空间模型 | 方向1 [7][6][9]；方向5 [24] |
| 拖延风险 | 何时会拖 | 历史延迟统计 | 双曲线贴现参数 + 特征模型 | 方向2 [12][16] |
| 个体化干预 | 何时给何种支持 | 规则（JITAI） | Q-learning / DTR / MRT 学规则 | 方向9 [12][13][14][16][18] |
| 难度自适应 | 下一题多难 | 规则阈值 | 多臂老虎机 | 方向9 [31] |
| 负荷上限 | 个人日上限 | 群体先验 + 保守值 | 个人负荷-绩效曲线拐点 | 方向5 [8][18] |
| 数据清洗 | 哪些耗时为异常 | 统一阈值（临时） | 个体/时段/任务特异异常检测 | 方向4 [24] |

> **升级判据**：文献明确指出 ML 优于"历史均值基线"是在**特征丰富、样本充足**时（方向4 [33][32][36]）；小样本下主动学习可减少数据需求（方向4 [30]）。因此不要一上来就上深度模型。具体模型拆分与阈值见 RO-2。

### Q4：哪些交给 LLM？什么情况不调用 LLM？

**回答口径**：LLM 擅长"理解含糊的人类语言、生成自然表达、在信息不全时给候选"；不擅长"保证 100% 正确、可审计、可重复"。方向10 结论一致：**LLM 只做候选生成与语义任务，硬约束交给确定性代码**。落地见 RO-6。

**A. 适合交给 LLM 的任务**

| 任务 | 为什么适合 | 依据 |
|---|---|---|
| 把含糊目标翻译成结构化目标（"我想变强"→可验证目标） | 需要语义理解 | 方向10 [12][20] |
| 任务拆解 + 子目标命名 + 生成 if-then 线索 | 生成性、需要语言 | 方向3 [12][16][17][9][10] |
| 生成反馈话术（结构化、指向任务） | 需要表达多样性 | 方向9 [7][8][20][21] |
| 生成测验题 / 复习问题 | 生成性任务 | 方向8 [3][7] |
| 诊断拖延借口、处理任务厌恶情绪 | 需要自然语言理解 | 方向2 [15][19][22] |
| 把规则校验失败翻译成"可读的批评"再回灌 | 语义转换 | 方向10 [20] |
| 把历史成功方案检索后做 few-shot | 检索增强 | 方向10 [13][14][15] |

**B. 不该调用 LLM 的情况（必须走确定性路径）**

| 条件 | 动作 | 依据 |
|---|---|---|
| 目标可形式化（依赖/时限/优先级明确） | 拓扑排序 + 规则 + 调度器 | 方向10 [12] |
| 规则 + 模板已能覆盖 | 直接模板渲染 | 方向10 [1][2][3] |
| 前一环节已通过规则校验、且任务简单 | 跳过 LLM，复用缓存/模板 | 方向10 [1][2][7] |
| 需要 100% 正确/可审计（硬约束、排程、校验） | 只用 RuleEngine | 方向10 [11][16][17][19][20] |
| 有相似历史成功计划可复用 | 检索后直接套用 | 方向10 [13][14] |
| 任务是纯计算/纯查询 | 工具/DB/确定性算法 | 方向10 [8][9][10] |

**C. "要不要升级到更贵的 LLM / 要不要放弃"的判断信号**

| 信号 | 含义 | 依据 |
|---|---|---|
| 采样分歧度高 | 多次生成结果不一致 → 不确定 | 方向10 [27] |
| 规则校验失败 | 候选不合格 → 需要重生成或升级 | 方向10 [20] |
| 不确定性超阈值 | 宁可不答（abstention）也不硬编 | 方向10 [6][5] |

**D. Verifier（验证器）设计**：步骤级验证（方向10 [16][17]）；外部验证器优于自省（方向10 [11]）；机器可读的结构化批评回灌 replan（方向10 [20]）；输出层语法约束（方向10 [25]）；LLM 不得直接碰数据库（方向10 [8][10]）。

## 4. 方案设计（11 方向 → 系统变量 → 实现 映射表）

> 本节把 11 个方向的发现压缩为 8 组"研究发现 → 系统变量 → 可能实现 → 证据ID"映射。这是 RO-2~RO-6 设计的需求原料；详细实现分别见各 RO。

### 4.9 反直觉与不能预设清单（R-01–R-28）

> 迁移自 `00-汇总映射.md` §四（原 §4.1–4.6），逐条保留来源方向与证据ID；**不引入新文献**。
> 用途：设计评审前逐条过一遍，检查有没有踩"按直觉做很可能错"的坑。每条：**直觉误区 → 文献实际 → 设计含义 → 证据ID（强度）**。
> 原文档 "R-13 / R-01" 等编号在本节保留；与 RO-1 §2 Q1 的规则编号（R1–R21）是两套体系，勿混用。

#### 4.9.1 压力/负荷类

**R-01 压力不能预设成"必须减小"**
- 直觉误区：压力=坏东西，应尽量降低。
- 文献实际：压力对绩效的影响**损害、促进、倒 U、无关四类并存**，取决于任务认知类型×压力强度×个体评价×测量通道。`强度：中强`（方向6 [7][8][9][11][20][21]）
- 设计含义：不要写"检测到压力就降难度"的全局规则；改为个体化、任务条件化，并记录"压力来源类型"。

**R-02 "绩效没变"不代表"没有压力成本"**
- 直觉误区：完成率正常说明状态良好。
- 文献实际：补偿控制机制下主任务表现可维持，但代价转移到质量、副任务、疲劳。`强度：中强`（方向6 [6]）
- 设计含义：监控要多指标（完成率 + 质量 + 放弃率 + 疲劳），不能只看完成率。

**R-03 连续高负荷 ≠ 绝对不能连续**
- 直觉误区："高认知任务不能连续"写成硬禁令。
- 文献实际：证据支持的是"连续高负荷会累积损伤，需缓冲/降级"。`强度：强`（方向5 [12][13][15]；方向1 [2][4]）
- 设计含义：规则写成"连续 N 个高负荷任务后强制缓冲"，而非"禁止相邻"。

**R-04 "每日任务量上限"没有普适数值**
- 直觉误区：查到一个"每天不超过 X 小时"的数字写死。
- 文献实际：存在个体化负荷红线，但**没有普适固定数值**。`强度：中强`（方向5 [8][18]）
- 设计含义：上限由个人负荷-绩效历史估计，系统冷启动用保守群体先验并快速个性化。

**R-05 自我损耗（意志力耗尽）可能被夸大**
- 直觉误区：把"意志力像电池会耗尽"写进规则引擎。
- 文献实际：高功效预注册研究未发现任务时长/顺序影响自我控制表现；偏倚敏感元分析提示疲劳效应可能被高估。`强度：高`（方向1 [8][16]）
- 设计含义：疲劳建模保守起步、在线校准；不写死"做久了必然变差"。

**R-06 认知疲劳对某些学习反而是"增强"**
- 直觉误区：疲劳对所有任务都是负效应。
- 文献实际：有研究发现认知疲劳反而增强统计语言学习。`强度：中`（方向1 [24]）
- 设计含义：给疲劳建模留出"任务类型交互项"，不要全局惩罚。

**R-07 知道任务何时结束，本身就能提升表现**
- 直觉误区：只关注任务内容，忽略"能不能看到头"。
- 文献实际：知道任务结束时间会提升认知表现、降低疲劳感。`强度：中`（方向1 [13]）
- 设计含义：给任务显示预计结束点/剩余量（与目标梯度 方向3 [18] 一致），是零成本干预。

#### 4.9.2 任务拆解类

**R-08 拆解并非总是有益**
- 直觉误区：越细越好，拆到最小步。
- 文献实际：不确定性过高或参数不利时，分解式决策反而更差；软件工程也警示按步骤细切增加耦合/实现成本。`强度：强`（方向3 [28][24]）
- 设计含义：拆到"可按边界独立完成"即可，且必须配建议默认值；高不确定性任务不盲目细分。

**R-09 只给大目标可能比不给目标更差**
- 直觉误区：先展示"30 天学完高数"激励用户。
- 文献实际：只给远距离目标组的产出低于"尽力而为"组；"近端+远端"才显著更好。`强度：强`（方向3 [5]）
- 设计含义：任何大目标都必须配近端子目标（R4）。

**R-10 子目标失败会反噬总目标承诺**
- 直觉误区：子目标失败只影响那一步。
- 文献实际：目标不重要时，单次子目标失败即降低总目标承诺与后续意向。`强度：中强`（方向3 [21]）
- 设计含义：失败后触发动机修复（R8），并周期性强化目标重要性。

**R-11 子目标标注在编程任务里效应会打折**
- 直觉误区：把数学/科学里的子目标效应直接搬到所有任务。
- 文献实际：CS 入门任务中子目标标签增益未稳定复现，结果混合。`强度：中`（方向3 [14]）
- 设计含义：按任务类型参数化拆解呈现方式，并做 A/B。

**R-12 拆解会改变估时（通常是变大）**
- 直觉误区：整体估时和分拆估时应该差不多。
- 文献实际：子任务估时之和显著大于整体估时（segmentation effect），更接近现实。`强度：中强`（方向3 [23]）
- 设计含义：大任务先拆再估（R16/方向4 [5] 的姊妹结论）。

#### 4.9.3 耗时/预测类

**R-13 "人总是低估耗时"是错的**
- 直觉误区：给所有估时乘一个 1.5 的乐观系数。
- 文献实际：低估在工程/管理文献更常见，心理学文献并非如此；短任务常高估；"小任务高估、大任务低估"可能是统计假象。`强度：强`（方向4 [3][4][8]）
- 设计含义：分域、分任务类型、分用户校准，绝不内置固定系数。

**R-14 时间限制会"污染"估时**
- 直觉误区：用 deadline 推断任务大小。
- 文献实际：时间限制越长，估得越久，即使知道限制是任意的。`强度：中强`（方向4 [5]）
- 设计含义：估时特征白名单排除 deadline/可用时长（R16）。

**R-15 计划得越多，时间偏差可能越大**
- 直觉误区：让用户把计划写得越细，估时越准。
- 文献实际：对某资源计划越多，该资源的规划谬误越大（"计划的讽刺效应"，时间 vs 金钱）。`强度：中`（方向4 [7]，工作论文）
- 设计含义：估时校准靠历史数据，而不是逼用户细化计划。

**R-16 个体学习曲线不是平滑的**
- 直觉误区：用一条平滑幂律外推用户未来耗时。
- 文献实际：分段幂律显著优于单一幂律；策略切换处会短暂下降再超越。`强度：强`（方向4 [16]）
- 设计含义：做变点检测/分段建模，检测到提速后重估倍率。

**R-17 低估有害、适度高估有益**
- 直觉误区：追求"无偏"点估计。
- 文献实际：比预期更久（PE−）恶化情绪、影响投入；比预期更短（PE+）改善情绪。`强度：中强`（方向4 [39]，预印本）
- 设计含义：默认输出保守区间（R17）；这是"闭环反馈"的设计约束，不只是统计问题。

**R-18 主观时长 ≠ 实际耗时**
- 直觉误区：让用户"感觉花了多久"当标签。
- 文献实际：时间知觉受难度与情绪影响，与实际时长分离。`强度：中高`（方向4 [38]）
- 设计含义：主客观两类数据分开存、分开用。

#### 4.9.4 拖延/反馈类

**R-19 提醒不是越多越好**
- 直觉误区：多提醒能防拖延。
- 文献实际：预期性提醒可能助长拖延；反馈频率过高不利学习；中等长度单一时限表现最差。`强度：中~中强`（方向2 [17]；方向9 [6][9][10]；方向2 [14]）
- 设计含义：多段紧时限 + 非预期提醒 + 随机检查点；反馈降频（R14/R19）。

**R-20 不是所有拖延都是"病"**
- 直觉误区：检测到拖延就催促/惩罚。
- 文献实际：主动拖延者可能有策略并表现更好，不应被打压。`强度：中`（方向2 [10][21]）
- 设计含义：分流主动/被动拖延；对被动拖延才介入。

**R-21 拖延是情绪调节问题，不只是时间管理**
- 直觉误区：给更多时间管理工具就能解决。
- 文献实际：CBT/动机性/情绪调节取向干预优于纯时间管理训练；拖延是短期情绪调节优先。`强度：中~强`（方向2 [11][22]）
- 设计含义：反馈话术偏向降低任务情绪负担，而非说教"要自律"。

**R-22 自我效能与拖延互为因果（循环）**
- 直觉误区：把拖延当单次行为。
- 文献实际：纵向交叉滞后证据支持"低自我效能↔拖延"的恶性/良性循环。`强度：中高`（方向2 [23]）
- 设计含义：主动打破恶性循环——先给容易成功的任务、即时正反馈。

#### 4.9.5 节律/个体差异类

**R-23 节律型的主效应很弱，必须个体化**
- 直觉误区：按"早鸟/夜猫"群体标签排程。
- 文献实际：chronotype 与成绩的元分析效应量仅 r≈0.14；个体内测量才可靠。`强度：高`（方向7 [3][7][11]）
- 设计含义：用个体内多时点行为数据推断个人峰值窗口，而非问卷标签。

**R-24 不同任务类型对时段敏感度不同**
- 直觉误区：所有任务都往"黄金时段"塞。
- 文献实际：流体认知任务对时刻敏感，晶体任务（复习/阅读）不敏感。`强度：高`（方向7 [13]）
- 设计含义：按时段敏感度分配，把黄金时段留给真正需要的任务。

**R-25 群体均值会掩盖个体差异**
- 直觉误区：用平均值当默认。
- 文献实际：组水平分析常掩盖亚组差异；个体差异是多维稳定的。`强度：中高~强`（方向11 [21][14][15]；方向4 [21]）
- 设计含义：所有预测必须用户级；冷启动用先验+快速个性化。

#### 4.9.6 LLM/系统可靠性类

**R-26 换更强/更贵的模型不等于能规划**
- 直觉误区：升级模型就不用校验了。
- 文献实际：对 o1 的 PlanBench 评测仍显示规划困难；立场论文与 LLM-Modulo 明确"LLM 不能单独规划"。`强度：中强~强`（方向10 [18][19][20]）
- 设计含义：验证器是必需品（R1）；模型升级只降低调用频率，不取消校验。

**R-27 让 LLM 自我反省不可靠**
- 直觉误区：让模型"再检查一遍自己"。
- 文献实际：外部验证器 > 内部自省；自省在部分任务无效。`强度：强`（方向10 [11][21][19]）
- 设计含义：验证必须外置（规则/工具/第二模型带工具），不是同一模型自说自话。

**R-28 长程 Agent 成功率本就低**
- 直觉误区：闭环能稳定完成多步任务。
- 文献实际：AgentBench/WebArena 等显示长程多步成功率有限。`强度：强`（方向10 [29][30][31]）
- 设计含义：指标设现实值；给用户"可能失败"的预期；关键步骤人工兜底。

> **与 §2 Q1 的关系**：本节是"不能预设"清单，对应到规则即 §2 Q1 的 R1–R21 与 RO-5 §4.3 的 15 条 P0 规则；本节不新增规则，只保留反直觉提示。
