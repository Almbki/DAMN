# 任务类型接口与数据流

> **这份文档记录什么**：任务类型的现状、四类规划模式（ONE_OFF / RECURRING /
> PROJECT / PROJECT+RECURRING）的字段契约，以及「添加任务 → 待拆解 → LLM 拆解
> → 数据库 → 待办」每一层读取/修改/存储了哪些参数。
>
> **怎么使用**：你准备重构 prompt，重点看第 3 节（字段矩阵）、第 4 节（数据流）、
> 第 5 节（每个 prompt 的输入/输出 schema）。第 2 节解释为什么「长期」和「常规」
> 以前看起来一样。第 6 节是可复制的四类请求示例。

---

## 1. 现在的任务类型（改造前）

### 1.1 三个层级的概念

| 层 | 枚举 | 值 | 用途 |
|---|---|---|---|
| Goal 语义 | `GoalType` | `short_term / long_term / project / habit / other` | 目标分类（历史字段） |
| Task 实例行为 | `TaskKind` | `one_off / long_term / routine` | 具体 task 行怎么重复 |
| 新 Goal 规划模式 | `PlanningMode` | `one_off / recurring / project / project_recurring` | 本次新增的产品层 4 类 |

### 1.2 为什么以前「长期」和「常规」界面一样

前端 `task-add-dialog.tsx` 原来把 `long_term` 和 `routine` 都放进同一个
`isSeries = kind !== 'one_off'` 分支，因此：

- 两者都显示：开始/结束日期、每天投入、重复日、目标量；
- 后端 `plan_drafter` 对两者都走 `_materialize_recurring`；
- 唯一区别是 `task_kind` 标签和 `series_id` 后缀：
  - `long_term` → `series_id = goal-1-long_term`
  - `routine` → `series_id = goal-1-routine`
- `goal_type` 映射：`long_term → long_term`，`routine → habit`。

**行为上没有任何区别**。这是历史设计的遗留：当时只有「一次性 vs 按天拆分」，
`long_term` / `routine` 只是语义标签。真正的问题不是 UI 一样，而是：

- `PROJECT` 也被错误地映射成 `long_term`，于是「学完高数」会被每天复制；
- 没有「项目 + 节奏」这个组合；
- LLM 的语义分类没有进入 deterministic 层。

## 2. 四类规划模式（本次设计）

| 模式 | 核心问题 | 例子 | 日期/节奏 | 内容形态 |
|---|---|---|---|---|
| `one_off` | 完成一次是否就结束？ | 写实验报告 | 一个 deadline | 单个 task |
| `recurring` | 同一种行为是否按明确规律重复？ | 每天背单词 | start/deadline + daily/weekly | 一个 reusable template，按日期展开 |
| `project` | 是否存在有意义的内容/阶段推进？ | 学完高数 | start/deadline，无节奏 | 有限 work-unit 序列 |
| `project_recurring` | 项目推进是否同时有重复节奏？ | 每天学高数直到学完 | start/deadline + daily/weekly | work-unit 序列按 occurrence 逐个推进 |

### 2.1 关键语义

- **project_recurring 不是「每天复制同一个任务」**，而是：
  - project 提供有限、有序的 work units（极限、导数、微分、积分…）；
  - recurrence 提供日期槽位（每天/每周）；
  - deterministic 层把第 i 个 work unit 放到第 i 个 occurrence date。
- 如果 work units 多于日期槽位：多出的 work units 保留为 deadline-bound
  一次性 task（不会被丢弃），由 scheduler 在截止日期前安排。
- 如果 work units 少于日期槽位：项目提前完成，series 结束于最后一个被使用的
  occurrence date。
- 同一 series 同一 occurrence_date 最多一个 task。

### 2.2 LLM 与 deterministic 的分工

LLM（`goal_analysis.md`）只输出 **3 类语义** + 可选 recurrence + work units：

```
goal_kind: one_off | recurring | project
recurrence: { frequency: daily|weekly, interval, weekdays }   # project 也可以有
work_units: [{ title, description, estimated_minutes }]        # project 用
```

`project_recurring` 是 deterministic 组合：`goal_kind=project` + 非空 `recurrence`。
LLM 不计算天数、不枚举日期、不输出「第1天」。

## 3. 字段矩阵（前后端 / DB）

### 3.1 Goal 创建/更新请求（`GoalCreate` / `GoalUpdate` / `PlanGoalCreate` / `DecomposeGoal`）

| 字段 | 类型 | 何时必填 | 说明 |
|---|---|---|---|
| `title` | string | 总是 | 任务/目标标题 |
| `description` | string | 选填 | 项目/课程写大纲或阶段；会进入 prompt |
| `planning_mode` | `one_off / recurring / project / project_recurring` | 新客户端建议总是 | 4 类产品模式；缺省时后端从 legacy 推导 |
| `goal_type` | `short_term / long_term / project / habit / other` | 选填 | 历史字段，保留兼容 |
| `task_kind` | `one_off / long_term / routine` | 选填 | 历史字段，仅用于 task 实例/兼容 |
| `start_date` | date | recurring / project / project_recurring | 生命周期起点 |
| `deadline` | datetime | one_off / project / project_recurring；recurring 可选 | 截止/结束 |
| `recurrence_frequency` | `daily / weekly` | recurring / project_recurring | 显式节奏 |
| `recurrence_interval` | int >= 1 | 选填，默认 1 | 每 N 天/周 |
| `recurrence_weekdays` | int[]（0=Mon..6=Sun） | weekly 时 | 空/7 个 = daily |
| `daily_target_minutes` | int | recurring / project_recurring | 每次 occurrence 的分钟数 |
| `estimated_minutes` | int | 选填 | project 总工作量提示 |
| `target_amount` / `target_unit` | int / string | 选填 | 可测量目标（如 20 词） |
| `priority` | 1..4 | 选填 | 优先级 |
| `subject` / `task_type` | string | 选填 | 放在 `goal.options` |

### 3.2 DB（`goals` 表）

| 列 | 类型 | 说明 |
|---|---|---|
| `planning_mode` | varchar(32), nullable | 4 类模式 |
| `recurrence_frequency` | varchar(16), nullable | `daily` / `weekly` |
| `recurrence_interval` | int, nullable | 默认 1 |
| `start_date` / `deadline` | date / timestamptz | 生命周期 |
| `recurrence_weekdays` | json | 周几 |
| `daily_target_minutes` | int | 每次投入 |
| `task_kind` / `goal_type` | varchar | 历史兼容 |
| `options` | json | subject/task_type |

`tasks` 表不新增列；task 实例仍用：

| 列 | 说明 |
|---|---|
| `task_kind` | recurring occurrence → `routine`/`long_term`；project/project_recurring step → `one_off` |
| `series_id` | recurring: `goal-{i}-routine/long_term`；project: `goal-{i}-project` |
| `series_index` | 第几个 occurrence / work unit |
| `occurrence_date` | recurring / project_recurring 的日期；project 为 null |

### 3.3 前端字段（`PendingTaskInput` / `PendingTask`）

| 字段 | 说明 |
|---|---|
| `planningMode` | 4 类模式，表单直接选择 |
| `recurrenceFrequency` | `daily` / `weekly`（由重复日推导：7 天=daily，否则 weekly） |
| `recurrenceInterval` | 默认 1 |
| `taskKind` | 兼容字段，由 `taskKindFromPlanningMode` 推导 |
| `startDate` / `dueDate` | 生命周期 |
| `dailyTargetMinutes` | 每次投入 |
| `recurrenceWeekdays` | 周几 |
| `targetAmount` / `targetUnit` | 目标量 |

前端 `TaskAddDialog` 现在有 4 个选项：
`一次性 / 重复习惯 / 项目·课程 / 项目 + 节奏`。

- `重复习惯`：显示重复日、每天投入、目标量；
- `项目·课程`：显示开始/完成日期 + 大纲提示，不显示重复日；
- `项目 + 节奏`：显示开始/完成日期 + 重复日 + 每天投入 + 大纲提示。

## 4. 从「添加新任务」到「待办」的完整数据流

下面每一层都标出 **读取 / 修改 / 返回存储**。

### 4.1 前端：添加任务（待拆解清单）

文件：`new_frontend/src/components/task-add-dialog.tsx`

- **读取**：用户输入 `title / priority / mode / dates / notes / dailyTarget /
  weekdays / target`；编辑时读 `initial`（`PendingTask`）。
- **修改**：本地 state。
- **返回**：`PendingTaskInput`：
  ```
  {
    title, priority, dueDate, notes,
    taskKind, planningMode, recurrenceFrequency, recurrenceInterval,
    startDate, dailyTargetMinutes, recurrenceWeekdays, targetAmount, targetUnit
  }
  ```
- `addPendingTask`（`state/api-plan.tsx`）：
  - **读取**：`PendingTaskInput`。
  - **修改**：本地 `pendingTasks`（负 id 占位）。
  - **存储**：`POST /goals` 创建 `status='draft'` 的 goal（真实 id 回填本地）。
    - payload：`title, description(notes), status:'draft', deadline, priority,
      goal_type, task_kind, planning_mode, recurrence_frequency,
      recurrence_interval, start_date, daily_target_minutes,
      recurrence_weekdays, target_amount, target_unit`。
    - DB：`goals` 行（`status='draft'`）。

### 4.2 前端：点「拆解」

文件：`new_frontend/src/state/api-plan.tsx` → `buildGenerateRequest`

- **读取**：`pendingTasks` + preferences。
- **修改**：无。
- **发送**：`POST /plans/preview` / `decompose`，`PlanGenerateRequest`：
  ```
  {
    goals: [PlanGoalCreate...],   // 每个 pending task
    plan_title,
    start_date?, end_date?,       // 可省略，后端默认 today+13
    available_minutes_per_day?, daily_limit_minutes?,
    buffer_minutes?, high_cognitive_max_per_day?,
    timezone?
  }
  ```
  `PlanGoalCreate` 字段见 3.1；新字段是 `planning_mode`、
  `recurrence_frequency`、`recurrence_interval`。

### 4.3 API：请求映射

文件：`app/api/v1/plans.py` → `_to_generation_request` / `_decompose_request`

- **读取**：`PlanGenerateRequest` / `DecomposeRequest`。
- **修改**：`start = payload.start_date or today`；
  `end = payload.end_date or today + 13`；每个 goal 映射为 `GoalInput`。
- **返回**：`PlannerRequest`（`app/agent/state.py`）：
  - `goals: GoalInput[]`（含 `planning_mode / recurrence_frequency /
    recurrence_interval / start_date / deadline / daily_target_minutes /
    recurrence_weekdays / task_kind / goal_type`）
  - `start_date`, `end_date`, `preferences`, `profile`, `timezone`, `user_id`.

### 4.4 Service：先落 goal，再跑图

文件：`app/application/services/plan_service.py` → `generate_preview`

- **读取**：`PlannerRequest`。
- **修改**：`_persist_goals` 写入 `goals` 行；返回 `goal_id_map`
  （1-based 请求索引 → 真实 goal.id）。
- **存储**：`goals`（先 commit，preview 和 confirm 是两次请求）。
- **调用**：LangGraph initial workflow，`state.goals` + `goal_id_map` +
  `request`。

### 4.5 LangGraph 各节点

#### `load_context`
- **读取**：DB user/profile/preferences/memory/current plan/fixed events。
- **修改**：无。
- **写入 state**：`user_context: PlanningContext`、`current_plan`。

#### `goal_analysis`（prompt: `goal_analysis.md`）
- **读取**：`state.goals`（`GoalInput`）、`request.profile`、
  `request.execution_weight`。
- **LLM 输出**：`GoalAnalysisResult`：
  ```
  {
    goals: [{
      goal_id, title, objective, subtasks, constraints,
      goal_kind: "one_off" | "recurring" | "project",
      recurrence: { frequency, interval, weekdays } | null,
      work_units: [{ title, description, estimated_minutes }]
    }],
    summary, confidence
  }
  ```
- **修改**：`task_decomposer._normalise`：
  - recurring → 清空 `work_units`；
  - project → 保留 `recurrence`（用于 project_recurring）和 `work_units`；
  - one_off → 清空两者。
- **写入 state**：`goal_analysis`。

#### `theoretical_analysis`（prompt: `theoretical_analysis.md`）
- **读取**：goals（+ 当前实现的理论分析上下文）。
- **LLM 输出**：`TheoreticalAnalysisResult`：
  `{ items: [{title, learning_content, subtasks, video_minutes,
  reading_minutes, practice_minutes, total_minutes, difficulty,
  cognitive_load}], total_theoretical_minutes, overall_difficulty,
  cognitive_load, confidence }`
- **写入 state**：`theoretical_analysis`。

#### `user_situation_analysis`（prompt: `user_situation.md` + narrative）
- **读取**：`theoretical_analysis`、`user_context.user_model`（Level 1/2）。
- **输出**：`UserSituationResult`：
  `{ duration_factor, completion_ability, stress_state, fatigue_state,
  recommended_time_slot, predicted_duration, predicted_completion_probability,
  should_reduce_load, narrative, confidence }`
- **写入 state**：`user_situation`。

#### `plan_generation`（prompt: `initial_plan.md` / `replanning.md` / `adjustment.md`）
- **读取**：`state.goals`、`state.goal_analysis`、`theoretical_analysis`、
  `user_situation`、`preferences`、`preview`/`current_plan`、`user_adjustment`、
  `replan_reason`、`completed_task_titles`、`user_model_context`。
- **LLM 输出**：`PlanGenerationResult`：
  ```
  {
    title, start_date, end_date,
    tasks: [GeneratedTaskDraft...],
    series_specs: [],   // deterministic 层填，LLM 不需要输出
    confidence
  }
  ```
  `GeneratedTaskDraft` 关键字段：`title, description, goal_id,
  estimated_duration, predicted_duration, completion_probability,
  recommended_time_slot, predicted_stress, prediction_source, cognitive_load,
  priority, subject, standards, deadline, order_index, task_kind, series_id,
  series_index, occurrence_date, target_amount, target_unit, is_flexible`。
- **deterministic 修改**（`PlanDrafterTool._materialize`）：
  - `planning_mode` 解析：显式 `planning_mode` > `task_kind=ROUTINE/ONE_OFF` >
    LLM `goal_kind` > legacy `goal_type`；
  - `one_off`：保留 1+ 个 draft，清 series/occurrence；
  - `recurring`：LLM 只给一个 template；代码按 `RecurrenceRule` 生成每个
    occurrence，写 `series_id/series_index/occurrence_date/deadline`；
  - `project`：LLM `work_units`（或 drafts）→ 有限 drafts，写
    `series_id=goal-{i}-project`，无 occurrence；
  - `project_recurring`：project work units 与 occurrence dates 逐个配对；
    多余 work units 保留为 deadline-bound one-off；写 `series_specs`。
- **写入 state**：`plan_draft: PlanGenerationResult`（tasks + series_specs）。

#### `rule_validation`
- **读取**：`plan_draft.tasks`、preferences、goals。
- **修改**：scheduler 放置；RuleEngine 校验。
- **写入 state**：`candidate_plan: CandidateSchedule`、
  `rule_validation`、`rule_violations`。
- **关键规则**：`earliest_start`、`deadline`、`recurrence_consistency`
  （duplicate / wrong-day / incomplete / out-of-range）。

#### `plan_repair`（可选）
- **读取**：`plan_draft` + violations + candidate。
- **修改**：shift/drop 非 series draft；series/project 不丢弃。
- **写入 state**：`plan_draft`（更新 tasks）、`repaired_plan`、
  `candidate_plan`、`rule_validation`。

#### `preview`
- **读取**：`plan_draft`、`candidate_plan`、`rule_validation`、confidence。
- **写入 state**：`preview: PreviewPayload`：
  `thread_id, title, start_date, end_date, tasks[PreviewTask],
  rule_violations, confidence, adjustment_count, can_adjust, notes`。
- **返回 API**：`PreviewResponse { thread_id, preview, goals_persisted,
  degraded, warnings }`。

#### confirm → `plan_finalization`
- **读取**：`plan_draft`、`request`、`rule_validation`、goals。
- **修改**：plan `start_date/end_date` 取 goal/occurrence 生命周期。
- **写入 state**：`final_plan: FinalPlanPayload`：
  `{ title, start_date, end_date, tasks, confidence, trigger_source,
  rule_violations }`。

### 4.6 Service：落最终计划

文件：`plan_service._persist_final_plan`

- **读取**：`final_plan`、`candidate_plan`、`goal_id_map`、`request`。
- **修改**：
  - `plans`：version/status/title/start/end/parent/confidence/data_origin；
  - `tasks`：title/description/duration/cognitive_load/priority/
    scheduled_date/start_time/end_time/status/completion_probability/
    prediction_source/task_kind/series_id/series_index/occurrence_date/
    target_amount/target_unit/order_index；
  - `task_standards`：每个 draft.standards；
  - `prediction_logs`、`replan_events`（如适用）；
  - 未排上槽位的 occurrence 保留为 `PENDING`（不丢弃）。
- **存储**：`plans / tasks / task_standards / prediction_logs /
  replan_events`。
- **返回**：`PlanDetail` → `PlanRead`。

### 4.7 回到前端待办

- `GET /plans/{id}` → `PlanRead { tasks: TaskRead[], goals: GoalRead[] }`。
- `taskFromApi` / `goalFromApi` 映射到本地 `Task` / `Goal`；
  `series_id/series_index/occurrence_date` 已包含在 `TaskRead`。
- `applyPlan` 写入 store；`index.tsx` 渲染今日/本周。
- **注意**：前端目前只渲染今天 + 当前自然周，月视图是占位；这是 view
  horizon，不是数据截断。

## 5. 你重构 prompt 时的精确接口

### 5.1 `goal_analysis.md`

**输入变量**
- `goals`: `GoalInput[]` JSON，包含 `title, description, goal_type,
  planning_mode, start_date, deadline, priority, estimated_minutes, subject,
  task_type, task_kind, recurrence_frequency, recurrence_interval,
  daily_target_minutes, recurrence_weekdays, target_amount, target_unit`。
- `user_profile`: dict。
- `execution_weight`: float。

**必须输出** `GoalAnalysisResult`（`app/agent/schemas.py`）：
```json
{
  "goals": [
    {
      "goal_id": 1,
      "title": "...",
      "objective": "...",
      "subtasks": ["..."],
      "constraints": ["..."],
      "goal_kind": "one_off | recurring | project",
      "recurrence": {
        "frequency": "daily | weekly",
        "interval": 1,
        "weekdays": [0,1,2,3,4,5,6]
      },
      "work_units": [
        {"title": "极限", "description": "...", "estimated_minutes": 120}
      ]
    }
  ],
  "summary": "...",
  "confidence": 0.5
}
```
规则：
- recurring：`goal_kind=recurring` + `recurrence`；`work_units=[]`；
  不输出日期/「第N天」。
- project：`goal_kind=project` + `work_units`（5-30 个）；
  如果项目也有节奏，**同时**输出 `recurrence`（这就是 project_recurring）。
- one_off：`goal_kind=one_off`；`recurrence=null`；`work_units=[]`。
- 不要计算天数，不要枚举日期。

### 5.2 `initial_plan.md`

**输入变量**
- `goal_analysis`: 上面的 `GoalAnalysisResult` JSON。
- `theoretical_analysis`, `user_situation`, `user_model`, `goals`,
  `preferences`。

**必须输出** `PlanGenerationResult`：
```json
{
  "title": "...",
  "start_date": null,
  "end_date": null,
  "tasks": [
    {
      "title": "...",
      "description": "...",
      "goal_id": 1,
      "estimated_duration": 60,
      "predicted_duration": 60,
      "completion_probability": null,
      "recommended_time_slot": null,
      "predicted_stress": null,
      "prediction_source": null,
      "cognitive_load": "medium",
      "priority": 2,
      "subject": null,
      "standards": [],
      "deadline": null,
      "order_index": 0,
      "task_kind": "one_off",
      "series_id": null,
      "series_index": null,
      "occurrence_date": null,
      "target_amount": null,
      "target_unit": null,
      "is_flexible": true
    }
  ],
  "confidence": 0.5
}
```
规则：
- recurring：每个 goal **只输出一个 template draft**；不要按天输出；
  不要写「第1天」；`series_id/occurrence_date` 留 null（代码填）。
- project：输出有限、有序的 work-unit drafts（一个 topic 一个 draft）；
  `series_id/occurrence_date` 留 null。
- project_recurring：同 project（有限 work units），代码会把它们和
  recurrence dates 配对。
- one_off：一个或少量 draft。
- `goal_analysis` 里的 `recurrence` 决定节奏；不要在 draft 里写日期。

### 5.3 `replanning.md`

**输入变量**：`replan_reason, planning_context, user_model,
adjustment_decision, current_plan, progress`。

**输出**：同上 `PlanGenerationResult`。额外规则：
- recurring：保留 template，只输出一次；不重新枚举日期；不把 series 变 one-off。
- project / project_recurring：保留有限 work units，不每天重复。

### 5.4 `adjustment.md`

**输入变量**：`preview, user_adjustment, preferences, user_model,
adjustment_count`。

**输出**：同上 `PlanGenerationResult`。额外规则：
- 如果 preview 里有 `series_id/occurrence_date`，保持它们不变；
- 不合并不改日期，不把 series 变 one-off；
- 只改 title/description/estimated_duration/standards。

## 6. 四类请求示例

### 6.1 ONE_OFF：写实验报告
```json
{
  "goals": [{
    "title": "完成实验报告",
    "planning_mode": "one_off",
    "goal_type": "short_term",
    "task_kind": "one_off",
    "deadline": "2026-10-30T23:59:59",
    "estimated_minutes": 120
  }]
```
