## 2. Level 1：Trait Model V1

### 2.1 模型边界

Level 1 只输出：

- 5 个 domain 的 `theta`
- 每个 domain 的 `se`
- 每个 domain 的 95% `ci95`
- 每个 domain 的 `items_answered`
- 总题数与 `completed`

**不输出**：MBTI、high/medium/low 标签、LLM 人格描述、调度建议、task completion probability、30 facet theta。

### 2.2 版本与验证

```text
GRM:  samejima_grm / grm_v1, 120 items, 5 domains × 24
CAT:  Bayesian EAP, N(0,1) prior, max Fisher at EAP, min 4 / max 12, target SE 0.35
Validation: 619,150 respondents; overall MAE 0.198; RMSE 0.253
Average items/domain: 10.33
TRAIT_MODEL_V1_READY = YES
```

| Domain | Pearson r | MAE | RMSE | Mean items |
|---|---:|---:|---:|---:|
| N | 0.971 | 0.185 | 0.234 | 8.58 |
| E | 0.960 | 0.213 | 0.270 | 8.33 |
| O | 0.970 | 0.174 | 0.226 | 12.00 |
| A | 0.965 | 0.195 | 0.250 | 11.96 |
| C | 0.956 | 0.225 | 0.287 | 10.80 |

已知限制：

- O/A 经常触发 `max_items=12`，最终 SE 约 0.40–0.41。
- 第二层/第三层应把 `se` 当作不确定度，不要假设五个 domain 精度相同。
- 不要重新拟合 GRM、不要改 `grm_parameters.json` / `cat_config.json` 的版本值、不要做 30-facet / multidim IRT。

## 3. Level 2：DDSR-V1

### 3.1 模型边界

Level 2 只维护三个 Daily Dynamic States：

- `fatigue`
- `stress`
- `self_efficacy`

四类行为指标与状态严格分离：

- `initiation`
- `persistence`
- `goal_attainment`
- `procrastination_evidence`

**不输出**：执行力、自律分数、人格判断、心理诊断。

**不修改 Level 1**：只通过 `TraitContext.from_profile(profile)` 读取 N/E/O/A/C 的 theta/se 和版本元数据；不建立 Trait → State 权重。

### 3.2 版本

```text

Tests:  54 passed, 0 failed

```

### 3.3 输入契约

```python
from ddsr import DDSREngine, TraitContext
from ddsr.schemas import DayInput, TaskPlan, TaskExecution, ReflectionInput

engine = DDSREngine()                      # 默认读取 ddsr/config.json
trait = TraitContext.from_profile(profile) # profile = Level 1 的 dict

day = DayInput(
    date=...,
    task_plans=[TaskPlan(...)],
    task_executions=[TaskExecution(...)],
    reflection=ReflectionInput(
        day_review="...",          # A. 今天做得怎么样？
        stuck_points="...",        # B. 哪里卡住了？
        state_review="...",        # C. 今天状态怎么样？
        tomorrow_outlook="...",    # D. 明天怎么看？
    ),
    passive_context=None,          # V1 默认 null，且不解释
)

dynamic_state = engine.process_day(day, trait)
```

也可以多日 replay：

```python
profiles = engine.replay([day1, day2, ...], trait)
```

### 3.5 更新逻辑（简述）

**Stage 1 — Prediction**

```text
mu_d^-  = rho * mu_(d-1)^+ + (1-rho) * population_mean
var_d^- = rho^2 * var_(d-1)^+ + q^2
```

Day 1 cold start：`mu=0.5`，`sigma=0.25`。

**Stage 2 — Correction**

在 0–1 的 101 点网格上做 Bayes：

```text
posterior ∝ prior * product(evidence likelihoods)
```

- fatigue/stress/self-efficacy evidence → 对应状态
- goal attainment → self-efficacy only
- procrastination / interruption → 行为指标，不改状态
- 冲突证据保留并标记 `conflict`
- LLM 抽取失败 → fail-closed，不产生证据

**Prediction error**：

```text
e_d = posterior - prior
z_d = e_d / prior_uncertainty
```

**Next-day prior**：

```text
mu_(d+1)^- = rho * posterior + (1-rho) * population_mean
```

`next_day_prior` 保存 value + uncertainty，次日直接使用。

### 3.6 全部参数

完整参数表见：

- `level2/ddsr/config.json`
- `level2/level2_model_report.md`

关键默认值：

|---|---:|
| state scale | 0–1 |
| cold start mean | 0.5 |
| cold start SD | 0.25 |
| persistence rho | 0.6 |

| strength weights | .35 / .65 / 1.0 |

| uncertainty floor / ceiling | 0.02 / 0.50 |

**来源分类**：literature-supported design choice / engineering initialization / learned-or-personalized。V1 没有已学习的个性化参数；prediction error 只保存，不用于在线学习。

### 3.7 证据抽取

- 生产路径：`LLMEvidenceExtractor` + `LLMClient` 接口。
- 测试/离线 fallback：`RuleBasedEvidenceExtractor`。
- LLM 只能返回 `ExtractionResult(evidence=[EvidenceItem])`。
- `EvidenceItem` 的 `evidence_text` 必须是 reflection 的逐字子串。
- `extra="forbid"`：LLM 不能返回 `state_value`、`prediction`、`diagnosis` 等字段。
- 语义 guard：procrastination 必须 `voluntary=True` 且非外部原因；interruption 必须 `voluntary=False` 且外部原因。
- 当前没有绑定真实 LLM API；上线前需要注入真实 `LLMClient`，并用人工标注 gold set 验证 precision/recall。

## 4. Level 3 可以怎么用这些资产

### 4.1 稳定输入

Level 3 可以直接读取：

1. **TraitProfile V1**：5 个 theta + 5 个 se + version metadata。
2. **DynamicStateProfile V1**：三个 state 的 `value` / `uncertainty` / `prior` / `prediction_error` / `next_day_prior`。
3. **TaskPlan / TaskExecution**：如果需要任务级信息，使用同一 schema 或写 adapter。
4. **EvidenceItem**：如果需要审计证据，读取 `evidence.evidence_items`。
5. **Prediction error 历史**：作为未来个性化/冷启动研究的数据资产。

### 4.2 不要做的事

- 不要修改 Level 1 的 GRM/CAT 参数或重新拟合。
- 不要修改 Level 2 的 `ddsr/` 源码、config 版本或验证结果。
- 不要把 `DynamicStateProfile.fatigue/stress/self_efficacy` 当作人格特质。
- 不要把 `procrastination_evidence.candidate_task_ids` 当作 confirmed procrastination；只有 `confirmed` 才是用户明确报告的主动拖延。
- 不要把 `passive_context` 直接解释成拖延、疲劳或低自律。
- 不要在没有真实数据前声称 Level 2 的个性化学习已经实现。

### 4.3 建议的 Level 3 接入方式

如果 Level 3 是策略/调度/干预/解释层，建议：

```text
Level 1 TraitProfile V1
        +
Level 2 DynamicStateProfile V1
        ↓
Level 3 policy / scheduling / intervention / explanation
```

- 只读 Level 1/2 输出。
- 用 `value + uncertainty`，不要只用点估计。
- 用 `next_day_prior` 做前瞻；用 `prediction_error` 做监控/研究。
- 用 `behavioral_indicators` 做行为反馈，不要把它们变成“自律评分”。
- 如果 Level 3 需要新的状态或行为变量，在 Level 3 自己的 schema 中定义，不要反向修改 Level 2。

### 4.4 现有 Level 3 参考论文

`level3/` 根目录已有：

- Buehler, Griffin & Ross (1994), *Exploring the “Planning Fallacy”*（两份副本）
- van der Velde et al. (2024), *Large-scale evaluation of cold-start mitigation in adaptive fact learning*

这两类材料分别提示：

- **Planning fallacy**：用户对任务完成时间的预测可能系统性乐观；Level 3 若做计划/时长建议，需要处理这一偏差。
- **Cold-start**：新用户/新材料的第一天估计很难；Level 3 若做冷启动策略，应优先使用“任务/材料属性”而不是只依赖“用户是谁”。

> 这只是参考方向，不构成 Level 3 的具体模型要求；Level 3 的目标应由 Level 3 自己定义。
